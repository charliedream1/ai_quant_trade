# AI 工作台输入区增强方案

日期：2026-10-17 21:24，Codex。

状态：源码核查与方案完成，等待用户确认后实施。

## 需求与现状

输入区右下角需要选择运行后台、模型与思考强度；左下角提供添加附件入口，并支持拖入文件和图片。保持现有 Gradio 模块化工作台、满屏对话、可折叠侧栏与左栏下半部项目会话。

已检查本周 changelog、近期 Git 日志、前端设计和模块化方案。当前输入区只有文本、运行方式下拉框与发送按钮，文件预览并不会附加到模型请求。模型配置已有启用状态和明确模型 ID，但工作台发送链路没有透传模型 ID、思考强度或多模态内容。

当前 `src/strategy/cli_builder.py:CliBuilder.create_session()` 是本地模拟器，不会启动真正的 Codex、Trae 或 WorkBuddy。本机能找到 Codex CLI 可执行文件；这只能证明已安装，尚未验证登录状态、可用模型或真实调用成功。

## 输入区布局与交互

| 位置 | 内容与行为 |
| --- | --- |
| 输入区上部 | 保持紧凑的两行任务输入，允许适度增高；聊天记录继续占用剩余空间。 |
| 附件区域 | 文件以名称、类型和大小展示，图片带缩略图；可从待发送列表移除，失败时保留草稿。 |
| 左下角 | 加号或回形针按钮添加多个文件、图片；输入区域支持拖放，拖入时显示清晰的落点反馈。 |
| 右下角 | 依次选择后台、模型、思考强度，并提供唯一发送按钮；控件使用紧凑样式与可访问名称。 |
| 小窗口 | 工具栏在输入区内换行，限制附件预览高度；外层页面不出现整体滚动，聊天记录独立滚动。 |

优先使用 Gradio 原生多模态输入能力承接上传和拖放，结合现有样式实现工具栏。避免增加第二套前端框架或另开页面。键盘发送与点击发送复用相同的校验、参数快照和后台处理，防止重复提交。

## 后台与参数联动

1. 模型 API：从现有模型管理中读取已启用配置，保留“跟随后台默认”选项，明确选择时透传模型 ID，不改变系统默认模型。
2. Codex CLI：建议本轮新增真实非交互调用适配器，与策略构建页的旧模拟器分开；后台可用性、超时、最终回复和失败信息均真实反映执行结果。首次以项目上下文分析能力为范围，工作目录固定到本项目，采用只读模式；不在本轮增加自动修改项目文件的交互流程。
3. Trae 与 WorkBuddy：保持兼容已有标识，但在 AI 工作台标记未真实接入，不允许模拟产物冒充真实执行成功；策略构建页的旧接口保持兼容。
4. 思考强度：默认跟随后台设置；只列出所选后台及模型已配置支持的档位。普通模型禁用此控件，并提示不支持。不得因为参数不支持而悄悄丢弃用户选择、切换模型或重发收费请求。
5. API 模型的视觉能力、思考参数名称和支持档位，以及 CLI 可执行配置、模型清单、超时等集中放入 YAML；密钥继续使用已有环境变量配置。页面不写死模型名称，也不承诺自动发现任意兼容服务的模型能力。
6. 每次请求记录实际后台、模型、思考强度和附件摘要；后续界面切换不改变已经开始的请求。历史会话恢复时可核对当次使用的选项。

项目自身的模型 API 继续使用 OpenAI 兼容普通聊天生成，保留现有文本 REACT 与 json_repair，不引入结构化输出接口或 function call。外部 Codex CLI 使用其自带运行协议，不将其工具机制改造成项目自研 Agent 的工具协议。

## 文件与图片处理

- 首轮支持常用文本、代码、Markdown、CSV、JSON、YAML、PDF、DOCX，以及 PNG、JPEG、WebP；具体扩展名、数量、单文件大小、总大小、文本和图片预算放入配置。PDF/DOCX 复用现有解析器，不新增文档解析依赖。
- 文本和文档提取内容并保留文件名、来源说明后传给后台；图片以真实图片内容传给支持视觉的模型，Codex CLI 使用图片参数。不能只发送服务器文件路径或附件名称并声称模型已读取。
- 对不支持的格式、空文件、损坏图片、无可提取文本的文档、超限和不支持视觉的模型给出明确反馈；需要截断的内容注明截断，不静默丢失文件。
- 上传缓存、会话附件与验收文件均放在本项目内。服务器只接受合法上传来源，保存时使用独立标识并检查路径边界，不信任客户端提供的任意路径。
- 发送后的附件跟随会话保存；重载会话仍显示附件并能恢复必要上下文，避免图片只在首次请求有效。移除待发送附件只取消附加，不直接删除磁盘文件；文件清理依用户“删除前确认”规则执行。
- 附件作为当前对话上下文，不自动加入知识库；知识库现有导入流程继续独立使用。

## 最小修改范围

| 范围 | 预计调整 |
| --- | --- |
| 工作台页面 | `src/frontend/features/ai.py:render_ai()` 输入组件与回调参数。 |
| 工作台样式与交互 | `src/frontend/assets/styles/ai_console.css`、`src/frontend/assets/ai_console.js` 的紧凑工具栏、附件显示、拖放反馈与满屏回归。 |
| 输入服务 | 独立模块负责能力配置、模型选项、请求校验；`src/frontend/service/ai.py` 保留会话服务入口，避免继续堆积上传和进程处理逻辑。 |
| Agent 请求 | `src/agent/generic_agent_runtime.py:GenericAgentRuntime.run_once()` 和 `src/agent/llm_client.py:LLMClient.complete()` 通过可选参数传递所选模型、思考强度和图片，保持已有调用兼容。 |
| 新增适配模块 | 附件解析、保存与真实 Codex CLI 调用分别组织，避免超大函数；不替换策略构建模拟器。 |
| 配置与文档 | 新增输入区 YAML 配置；同步 README、前端设计、架构、模块使用说明及 changelog。若无需新增依赖，保持 requirements 不变。 |

## 验收

1. 单元测试覆盖模型与能力联动、真实请求参数、附件校验与上下文、文件路径边界、CLI 成功/失败/超时以及现有无附件调用兼容。
2. 集成测试使用可核查请求的兼容接口与 CLI 进程测试替身，确认文字、图片、模型与思考选项实际到达调用边界；测试替身结果与真实服务验证分别记录。
3. 已安装 CLI 的帮助和可用性先检查；真实调用只使用已有合法配置，不改动项目外的认证或环境文件。若登录、模型授权或接口可达性不足，报告具体阻碍，不将测试替身冒充真实 CLI 验证。
4. 浏览器模拟点击选择后台、模型和思考档位，上传与拖入文件/图片，移除待发送附件，发送并重载会话；检查能力不匹配、失败后草稿、重复点击和旧会话兼容。
5. 查看亮色、暗色及常用窗口尺寸截图，核对控件顺序、可访问名称、附件可读性、对话高度与无整体滚动；回归工作台其他入口、九模块导航和既有性能预算。
6. 完成 Ruff、mypy、pytest、依赖漏洞与安全检查，缺失工具如实记录；核对中文编码、设计说明和日志。结束时停止本轮启动的所有测试服务，确认端口释放；临时文件列清单并经用户确认后清理。
