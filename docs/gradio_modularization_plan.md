# Gradio-first 模块化整改实施方案

## 1. 技术决策

平台前端统一回到 Gradio 主路线。FastAPI 继续承载 REST API、WebSocket、帮助文档和 Gradio 挂载；`src/light_ui` 不再作为产品入口，也不再继续建设第二套页面。

本次整改针对的是当前单体结构，而不是替换 Gradio：

- `src/frontend/app.py` 在一个 `build_gradio_app()` 中创建全部页面、组件和事件。
- `src/frontend/services.py` 集中承担全部输入校验、领域调用和展示转换。
- 单个 `Blocks` 的 `/config` 包含全站组件和依赖，任意页面都要加载完整配置。
- 页面变量和跨区域回调集中在同一作用域，局部修改容易产生全局回归。

整改目标：

1. Gradio 是唯一主 UI，根路径直接进入持久 Gradio 工作台。
2. 一级业务域使用独立 `gr.Blocks` 应用和独立 URL。
3. 每个应用第一次访问时才构建，并分别缓存、启动各自的回调队列。
4. 页面、事件绑定、展示适配和测试按业务域共同归档。
5. 未迁移完成前保留旧 Gradio 单体作为兼容入口，验收后删除。
6. 页面构建阶段不访问行情、数据库大表、LLM 或外部网络。

## 2. 目标路由

| 路径 | Gradio 模块 | 主要范围 |
|------|-------------|----------|
| `/` | 重定向 | `/app/` |
| `/app/` | 持久工作台 | 同页模块导航、市场切换与最多三个最近模块实例 |
| `/app/dashboard/` | 投研看板 | 总览、自定义看板、账户与市场摘要 |
| `/app/market/` | 市场研究 | 行情、因子、新闻、个股、关系图谱、资源池、推荐 |
| `/app/research/` | 研报论文 | 研报、模型报告、论文 |
| `/app/strategy/` | 策略构建 | 生命周期、策略库、预制策略、上传、CLI 构建 |
| `/app/simulation/` | 策略仿真 | 回测、模拟交易、模拟归因 |
| `/app/live/` | 实盘 | 发布、风控、运行控制、归因 |
| `/app/ai/` | AI 工作台 | 操作台、洞察、专家、工作流、问数 |
| `/app/knowledge/` | 知识库 | 本地知识、RAG、远程知识源、学习专栏 |
| `/app/admin/` | 系统管理 | 任务、设置、环境、模型、MCP、Skill、帮助 |
| `/legacy-app/` | 迁移期兼容 | 当前完整单体 Gradio；验收后移除 |

工作台左侧导航切换独立模块，不再打开新的顶层页面，也不恢复包含全站页面的单体 `gr.Tabs`。模块和模块一级页面合并为左侧折叠导航；内容区只保留当前页面真正需要的明细 Tabs，可见导航最多两层。九个 `/app/<module>/` 路径继续作为独立调试和兼容入口。

## 3. 目标结构

```text
src/frontend/
├── app.py                    # 兼容导出，最终只保留装配入口
├── registry.py               # 模块描述、顺序、URL 与构建器
├── modular.py                # Blocks 外壳、主题、队列和统一页脚
├── mounting.py               # 独立应用延迟构建、队列启动与 ASGI 挂载
├── shell.py                  # 持久工作台、模块容器与客户端有界缓存
├── common/
│   ├── callbacks.py          # 错误转换、耗时和 operation_id 日志
│   ├── components.py         # Dataframe、Chatbot、状态区等公共组件
│   └── __init__.py
├── navigation.py             # Gradio 模块 URL 导航
├── theme.py                  # CSS、JS、主题和挂载选项
├── service/                  # 领域回调实现与共享展示转换
│   ├── foundation.py         # 配置、解析、缓存与表格基础
│   ├── visuals.py            # Plotly 与交易展示适配
│   ├── dashboard_views.py    # 看板 HTML 展示适配
│   ├── contracts.py          # 显式跨域调用契约
│   └── <domain>.py           # 各业务域回调实现
├── features/
│   ├── dashboard.py
│   ├── market.py
│   ├── research.py
│   ├── strategy.py
│   ├── simulation.py
│   ├── live.py
│   ├── ai.py
│   ├── knowledge.py
│   └── admin.py
└── handlers/
    ├── dashboard.py
    ├── market.py
    ├── research.py
    ├── strategy.py
    ├── simulation.py
    ├── live.py
    ├── ai.py
    ├── knowledge.py
    └── admin.py
```

每个 `features/<name>.py` 只创建本模块组件并绑定本模块事件。页面之间传递数据库 ID、稳定业务键或 URL 参数，不传递另一个 Gradio 应用中的组件对象或 `gr.State`。

## 4. 模块契约

注册表中的每个模块提供稳定元数据和独立构建器：

```python
GradioModule(
    key="market",
    title="市场研究",
    path="/app/market",
    order=20,
    build=build_market_app,
)
```

构建器必须返回独立 `gr.Blocks`，只初始化组件和轻量默认值。重数据通过 `load`、按钮或 Tab 首次选择事件获取；回调必须经过统一错误和耗时包装；模块不得读取其他页面的组件变量，也不得复制后端领域逻辑。

## 5. 服务层拆分

`FrontendService` 已完成兼容门面拆分，迁移结果如下：

1. 页面继续通过领域 handler 访问精确方法白名单，返回结构保持不变。
2. 实际回调按 dashboard、market、research、strategy、simulation、live、AI、knowledge、admin 和 assistant 归档。
3. 参数解析、缓存、表格、Plotly 和看板展示转换进入共享服务模块。
4. 明确需要复用的跨域工作流通过独立类型契约调用，不允许任意跨域访问。
5. `services.py` 保留 `FrontendService` 和既有常量、帮助函数的稳定导入路径，旧页面和扩展无需同步改写。

数据库、行情、任务、LLM 和交易逻辑继续由现有领域服务负责，前端层不得创建第二套实现。

## 6. 性能方案

- FastAPI 启动时只注册延迟 ASGI 包装，不构建任何 `Blocks`；模块首次访问时在当前事件循环启动自己的 Gradio 队列一次。
- 每个模块使用独立锁和独立缓存，首次请求只构建当前模块。
- 工作台只在第一次选择模块时创建同源 iframe，浏览器端按最近使用顺序保留三个实例；被回收模块再次进入时复用服务端已构建应用。
- 工作台侧栏支持展开/收起，窄屏自动转为横向导航；统一主题支持 `light`、`dark`、`system` 配置和浏览器本地覆盖，组件使用共享圆角与阴影变量保持视觉一致。
- 不在组件 `value=` 中执行行情、数据库聚合或 LLM 方法。
- 首屏只加载当前页面必要摘要，二级重型页面在首次选择或显式点击后加载。
- 同一页面多个输出使用聚合 bootstrap，避免重复查询。
- 大表采用分页、限制行数或摘要加详情模式。
- 稳定主数据和配置使用有界 TTL 缓存；订单、持仓和运行状态不使用长缓存。
- Qlib、回测、同步和 AI 工作流继续走后台任务，不阻塞页面线程。

性能门槛以整改前基线为对照：

- 常规业务模块的组件数和 `/config` 大小不超过旧单体的 40%；AI 工作台因新增自动化、MCP、Skill、知识库登记面板单独控制在 600KB 和 400 个组件以内。
- FastAPI 启动不触发 Gradio 页面构建。
- 默认投研看板构建不触发外部网络或重型领域调用。
- 普通模块热访问达到本地秒级。
- 页面切换不会构建未访问模块。

## 7. 实施阶段

### A. 基线与入口回归

- 固化旧 Gradio 页面、组件、事件和关键工作流清单。
- 根路径恢复到 Gradio。
- 停止轻量 HTML UI 路由和静态资源挂载。
- 启动信息、README 和测试统一使用 Gradio 主入口。

### B. 模块化基础设施

- 建立注册表、Blocks 工厂、公共组件、持久工作台和两层模块导航。
- 建立按模块延迟构建的 ASGI 挂载器。
- 增加模块隔离测试：访问一个模块不得构建或启动其他模块，当前模块的队列只启动一次。
- 旧单体迁移到 `/legacy-app/` 作为临时回退。

### C. 低风险模块迁移

- 迁移帮助、任务、设置、环境变量、模型、MCP 和 Skill。
- 迁移知识库、研报、论文和学习专栏。
- 每迁移一个模块立即补齐配置与回调测试。

### D. 核心交易模块迁移

- 迁移行情、因子、新闻、个股、关系图谱、资源池和推荐。
- 迁移策略构建、回测、模拟交易和模拟归因。
- 迁移实盘发布、风控、运行控制和实盘归因。

### E. AI 与总览迁移

- 拆分 AI 操作台、因子挖掘、洞察、专家、专家团和闭环工作流。
- 最后迁移总览，使其只聚合各领域的轻量摘要。
- 浮动 AI 助手改为可选公共组件，不在不需要的模块中创建。

### F. 清理兼容层

- 完成功能矩阵和浏览器审计。
- 移除 `/legacy-app/`、旧单体 `Blocks` 和 `src/light_ui`。
- 清理兼容门面、失效 CSS/JS、文档和测试。
- 输出最终性能对比和剩余风险清单。

## 8. 测试与验收

每个模块至少包含路由测试、`/config` 关键组件契约测试、构建不调用重型服务的隔离测试、handler 单元测试、核心回调冒烟测试和浏览器页面审计。

平台级验收：

- 旧 Gradio 功能矩阵全部有新路径或明确合并位置。
- 行情切换、文件上传、策略创建、回测、模拟交易、实盘控制、知识问答和模型配置工作流通过。
- 任一模块构建失败不影响其他模块和 REST API。
- 代理 `frontend_root_path`、静态资源缓存、gzip 和帮助文档正常。
- Ruff、类型检查、单元测试、集成测试和浏览器审计通过。

## 9. 回退纪律

- 迁移期间保留旧单体入口，模块验收后才移除对应旧代码。
- 不通过整体 Git 回退处理轻量 UI，避免覆盖并行修改。
- 路由切换、页面迁移和旧代码删除采用独立变更边界。
- 任何功能从旧页面删除前，必须有新模块测试和功能矩阵记录。
