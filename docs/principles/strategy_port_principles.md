# 策略标准端口原理说明

## 设计目标

策略标准端口的目标是让不同来源的策略都能以统一方式进入策略库、回测、模拟盘和后续实盘链路。策略来源包括人工上传、egs 示例、trae/workbuddy/codex 等 CLI 产物，以及后续外部策略迁移。

## 接入原则

| 原则 | 说明 |
|------|------|
| 先识别再执行 | 上传和导入阶段先做 AST 校验与入口识别，运行时加载只在校验通过后发生 |
| 适配器隔离 | StrategyBase 类、普通类和函数入口都先包装成统一端口，再交给引擎 |
| 展示不执行 | 创建和详情只做静态校验，不为展示执行模块顶层动作；实际加载先验证来源或SHA256复核 |
| 可信运行 | 内置/受控生成按已知源码识别，复核后的自定义源码进入有状态工作进程；源码变化使复核失效 |
| 示例可复用 | `egs/strategy_examples/` 同时服务页面导入、接口说明和自动化测试 |
| 页面可解释 | 策略详情展示入口类型、入口名称、能力列表和样例信号，方便人工确认 |

## 支持形态

| 形态 | 适用场景 |
|------|----------|
| StrategyBase 标准类 | 平台内长期维护、自研策略、需要继承基础能力的策略 |
| 普通类端口 | 外部类策略迁移、轻量策略对象、已有类方法命名不同的策略 |
| 函数端口 | 快速实验、CLI 生成短策略、单文件低复杂度策略 |

## 与回测的关系

标准端口静态预检只检查源码入口和声明，运行检查另行验证加载、调用及信号归一化。它不代表策略收益有效，也不替代完整历史行情回测。当前simple回测复用同一端口，提供日K、long/flat撮合、交易成本、复权选项、手数和仓位限制及绩效评估；实际历史覆盖、专业执行模型和真实券商能力仍需分别验证。执行边界见[安全与并发原理](security_concurrency.md)。

## 页面呈现原则

策略页面应该把“策略是否能加载”和“策略是否赚钱”分开展示。接口检查只回答前者；收益、回撤、交易次数和风险暴露应在回测和模拟交易页面展示。

## 当前验证边界

2026-10-17 的日期回退缺陷属于历史问题。当前 mock K 线映射到请求区间工作日；真实行情无区间内数据时失败，不使用区间外 K 线。截至 2026-10-21 已验证 13 套示例导入与回测，并重放三类模型及两套 ETF 的归档真实行情，仍不能证明任意策略或区间有效。

Qlib 回测选项已接入原生 Workflow 适配链路，但默认验收环境缺少完整依赖、数据和 Workflow，保持 blocked。依赖导入、登记及测试替身不等于实际训练回测通过。接口检查也不构成任意 Python 代码的安全沙箱。

操作见[策略导入](../usage/strategy_import.md)，撮合与曲线见[回测原理](backtest_metrics.md)。
