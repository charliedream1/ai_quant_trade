# 参数继承与试验复现

命名方案记录试验意图，单次覆盖记录本次差异，运行快照记录最终使用值。三者用途不同；仅保存一个 YAML 路径不能复现之后已被修改的试验。

## 后端生效顺序

由低到高依次为模型公共默认、源码声明默认、数据库中策略默认、所选方案、本次覆盖。嵌套对象按字段合并，列表整体替换；空对象保留下层字段。页面、REST 和 CLI 最终调用同一参数解析链路。

CLI 在发送前还有一层请求拼装：完整请求文件、策略参数文件、set 覆盖、显式业务选项依次叠加。这一层不会替代后端命名方案解析。客户端连接文件只设置地址和超时，不改变服务端数据模式。

## 为什么需要快照

| 证据 | 能回答的问题 |
| --- | --- |
| 参数值及来源 | 本次实际使用了什么，哪个层级覆盖了默认值 |
| 策略及依赖摘要 | 源码或环境是否变化 |
| 行情摘要与市场 | 数据是否相同，是否比较了不同市场或区间 |
| 执行假设 | 手数、仓位、费用、滑点、复权及订单方式是否一致 |

快照不等于完整归档数据，旧任务可能没有全部证据。稳定复现还需要对应行情文件和运行环境。调参应固定条件、限制比较次数并保留独立验证段；当前支持手动方案与比较，不提供自动参数搜索。

操作见[策略调参](../usage/strategy_parameters.md)。正式参数设计保留在项目 `doc/10_strategy_parameter_design.md`。
