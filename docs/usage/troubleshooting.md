# 排障指南

## `/app/` 提示 404

| 排查点 | 处理建议 |
|--------|----------|
| 端口被旧进程占用 | 先看启动日志中的端口预检结果，确认访问的是当前进程 |
| 访问地址缺少尾斜杠 | `/app` 会重定向到 `/app/`，建议直接使用启动日志打印的 Frontend 地址 |
| 反向代理前缀错误 | 本地启动时 `frontend_root_path` 保持空值，只有代理部署才设置 |

## 页面切换慢

当前使用持久导航和独立模块延迟挂载；首次进入模块需要构建组件，返回最近使用的模块会复用实例。图表、DataFrame 重排和外部行情冷启动仍可能耗时。父级页签不再自动刷新重数据，帮助文档使用静态站点，低时效数据使用日内缓存。

如果某个页面仍明显卡顿，优先记录具体路径、点击顺序和是否触发刷新按钮，再用页面巡检脚本生成截图和 JSON 结果。

## 行情或新闻失败

| 现象 | 处理建议 |
|------|----------|
| 代理断开或连接失败 | 默认行情 HTTP 不继承系统代理，可用 `ALL_IN_ONE_DATA_HTTP_TRUST_ENV=true` 显式开启 |
| 公开接口限流 | 降低刷新频率，检查 Eastmoney 节流配置 |
| 测试环境不需要公网 | 设置 `ALL_IN_ONE_DATA_MODE=mock` 使用本地样例数据 |
| 首页新闻数量不足 | 8 是展示上限，不是保证条数；检查实际新闻源、时间范围和当前市场，mock 数据不代表实时新闻 |
| 新闻初始化出现 UNIQUE 约束错误 | 2026-10-21 已修复并发去重写入；确认服务加载最新版本并重启，不要手工清空新闻库 |

## 模型调用失败

先检查环境变量是否导入，再检查模型配置中的 Base URL、模型名、API Key 变量名、Temperature、Max Tokens 和超时时间。模型测试会发起真实请求，不返回固定模拟成功。

## CLI 只有日志、没有回复

截至 2026-10-21，AI 工作台和悬浮窗的 Codex 对话使用本机 `codex exec --json` 只读事件流，状态、动作和助手正文会逐步显示；mock 模式默认禁用真实调用。需验收时，在服务环境设置 `ALL_IN_ONE_ENABLE_REAL_CLI=true` 后重启，并检查可执行文件和认证。Trae/WorkBuddy 未接入真实协议时显示不可用，不生成模拟日志。策略构建页旧 `CliBuilder` 不能当作真实对话 CLI。

2026-10-21 已修正工作台发送回调未被 Gradio 识别为生成器的问题；Enter 和按钮均可发送，悬浮 CLI 也逐事件更新。若出现“needed: 6, returned: 1”或把生成器显示成返回值，请确认服务加载了本次修复后的安全回调，并重启服务；只刷新浏览器不能替换已挂载的 Python 回调。多轮历史现在规范化文本内容块，不应再显示 text/type 字典串。

## Enter 不能发送

工作台、悬浮模型问答和悬浮 CLI 消息支持 Enter 发送、Shift+Enter 换行；中文输入法组合输入期间不会抢发。若浏览器缓存旧静态脚本，刷新模块或清空缓存后再检查 `ai_console.js`。

## 策略或仿真结果异常

先核对策略 ID、接口检查、启用状态、参数格式、账户名称是否重复、标的和资金。截至 2026-10-21 已验证 13 套示例的导入、启用和回测，并另行重放三类模型及两套 ETF 的归档真实行情；这不能替代新参数、新区间的验证。

特别注意实际曲线日期：mock K 线现在会映射到请求区间内的工作日；真实行情若没有可匹配日期会返回无历史错误，不再退回区间外 K 线。不要只看“已完成”、收益率或界面无异常；必须核对曲线日期、成交、持仓和成本。

零成交可能是信号未触发，不能一律判定为错误；先查看信号、历史点数、最小手数和仓位限制。模型策略至少需要两个日期对齐的标的，建议三个及以上，使用开盘价订单；样本不足会失败，不应用缩短训练窗口掩盖数据问题。

## Qlib 未就绪或无法回测

项目 `.venv-models` 已验证 LightGBM、XGBoost 和小型 MLP。因子监控另提供 `.venv-qlib` 独立信号分析后端，已实测 pyqlib 0.9.7 与真实行情 IC/RankIC；配置见[通用因子监控](factor_monitoring.md)。这不等于完整原生模型训练与组合 Workflow 已通过。其他环境能导入 pyqlib，也不能证明当前工作进程及其数据、配置就绪。

实验登记与 qrun 适配器支持 `qrun_path`/`ALL_IN_ONE_QLIB_QRUN`，回测页 Qlib 引擎复用 Workflow 记录链路；示例 provider 与 Workflow 仍需自行准备。排查时分别记录信号分析与原生 Workflow 的环境、数据、执行入口和产物。

先执行 `python egs/cli.py qlib status --format json` 查看当前服务诊断。只有原生运行成功并产生实际指标和逐日组合曲线，才能验证完整 Qlib 回测；只有指标时页面仅显示指标摘要。

## 智能洞察空白或较慢

先点击“刷新每日行情”并查看状态条。系统按需加载并复用当日行情快照；真实数据冷启动仍可能受外部源失败、限流和备用源回退影响，暖缓存通常更快。若仍为空，先核对数据模式、行情源可达性和服务日志，再重试，不要把空白摘要当成数据为零。

## 命令行失败或等待过久

| 现象 | 排查方式 |
| --- | --- |
| 退出码 2 | 检查 ID、参数拼写、请求字段；YAML 日期必须加引号；布尔业务参数显式填写 true/false |
| 退出码 3 | 检查服务地址、端口、代理及 API 前缀；CLI 不会自动启动后端 |
| 退出码 4 / 中断 130 | 执行结果可能未知；先查 backtest list、ai session show 或 agent list，不盲目重提 |
| HTTP 200 但退出码 5 | 业务执行 failed，读取 message 和 data 中的具体原因 |
| 退出码 6 | blocked、禁用或依赖缺失；查看能力边界，不以改成 mock 伪装真实成功 |
| 退出码 7 | 真实来源或复核结论不满足；--require-real 也拒绝没有来源证据的接口结果 |

脚本使用 `--format json` 读取 code、message、data、meta，同时检查进程退出码。查询失败任务的记录可以成功返回，仍需读取 data.status；更多见 [命令行](cli.md)。

## 文档或学习章节没有更新

帮助中心是构建后的静态站点，确认 `ALL_IN_ONE_HELP_DOCS_AUTO_BUILD=true` 后重启服务。关闭自动构建时，需要先更新构建产物；单纯刷新浏览器不会编译 Markdown。学习专栏新增章节后需重启以重新扫描目录，已有章节可点“刷新当前章节”。
