# 金融多 Agent 应用与项目落地

调研日期：2026-10-19。这里的 Agent 指产品中由大模型驱动的专职角色，不是本次开发助手的并行子任务。

## 实际应用与证据层级

| 案例 | 公开内容 | 证据层级 |
| --- | --- | --- |
| Man Group Alpha Assistant，2025-10-15 | 主控 Agent 调用专用工具和子 Agent，接入机构研究环境 | 机构公开的研究辅助应用案例；不是公开自动实盘交易证明 |
| Man Group AlphaTrend，2026-02-11 | 预定义分阶段流程，独立节点可并行，后续节点读取前序结果，关注可审计性 | 机构公开的投研工作流与验证案例；文中曲线为说明性模拟结果 |
| TradingAgents | 分析、研究、交易建议和风险角色协作，有可运行的开源框架 | 开源研究工具；仓库明确声明研究用途，不能视为机构实盘成绩 |

因此，多 Agent 在投研辅助与流程自动化方面有实际公开应用证据。公开材料不能证明多人设辩论就能稳定获利，也不能证明无需人工判断。

## 本项目：多 Agent 回测复核

复用项目已有 OpenAI 兼容接口，所有角色都使用普通文本生成，通过文本 ReAct 协议读取工具观察；生成的 JSON 必须经过 json_repair 和字段校验，不使用 function calling 或模型厂商的结构化输出接口。

| 阶段 | 输入与职责 | 输出 |
| --- | --- | --- |
| 模型分析员 | 读取训练、验证、预测和交易证据 | 对模型有效运行与数据口径的意见 |
| 风控审查员 | 检查成本、回撤、样本和数据来源，并读取前序意见 | 风险结论与需要补充的证据 |
| 独立复核员 | 读取所有前序角色结果和原始证据，寻找矛盾 | 复核意见与不同结论的原因 |
| 投研汇总员 | 汇总前面角色结果，遵守系统检查与否决 | 研究报告、证据引用和后续验证项 |

首版按角色顺序执行，减少并发请求与输出冲突；每个角色有独立上下文与职责。它是真实的多次模型调用和结果交接，不是一次生成中模拟四个角色。页面显示角色状态、工具次数、耗时、模型名和最终报告。

各角色可以复用同一底座模型；角色分工和上下文隔离不等于统计独立，不能把多角色赞成直接当成更高可信度的证明。有效性仍需通过真实数据、确定性检查和人工复核评价。

## 证据与运行边界

- 只读取明确指定且已完成的回测快照，不将当前新闻混入历史回测判断。
- 工具仅提供回测证据与前序角色结果，不提供委托、源码执行、任意网络和文件写入能力。
- 每个角色必须实际读取其引用的证据；必须读取已有同事结果后才可结束，未知引用或超出轮数预算明确失败。
- 任何角色的否决都不能被后续角色的赞成覆盖；合成数据和缺少训练证据等系统检查会限制最终研究结论。
- 无真实模型配置、接口错误、无效输出都记失败；mock-llm 不得作为实际多 Agent 成功结果。
- 单次报告记录运行标识、回测标识、角色输出、工具轨迹、时间和结果。仅生成研究复核报告，不自动交易。

入口：AI工作台 → 工作流中心 → 专家团 → 多Agent回测复核。配置位于 `egs/config/agents/research_team.yaml`。
