## 目标与页面

在 AI 工作台的智能洞察中提供固化的市场复盘与个股分析。用户点击左侧任务按钮即开始执行，系统加载项目内 Skill、获取数据、调用模型、核查证据并生成可在右侧阅读的 HTML 报告。

左侧主要操作为“Market Review · 市场复盘”和“Single Stock Analysis · 个股分析”。市场复盘默认使用最近可用交易日和已选市场，可调整到月度；个股分析只需填写证券代码或名称。执行后端始终可见，模型与任务设置折叠放置，复用系统已启用模型或已接通的 Codex CLI。默认提示词固定，用户无需复制 Skill 或编写任务描述。报告面板首次进入时动态构建，激活状态保留，避免主工作台初始化加载全部报告控件。

右侧显示实际阶段、耗时、来源与报告。完成后提供目录、摘要、图表、正文、数据来源及下载入口；可查看历史报告。原每日行情和问数保留入口，不因新报告功能回退。

market-review 包约 44 个文件，stock-analysis 约 9 个文件，stock-analysis-23 约 4 个文件。本机 market-review 还引用 neodata、公众号采集、固定 Windows Python 和用户目录；stock-analysis 的部分功能会使用用户目录账本。原样执行无法保证跨平台或项目文件边界。

## Skill 纳入与适配原则

项目内新增 src/skills，按 market_review、single_stock_analysis 分类保存实际使用的 SKILL.md、阶段提示词、排版与必要参考资料，登记本机来源、版本和文件摘要。保留来源说明；适配清单明确哪些资源原样复制、哪些经过调整。

原始 Skill 中涉及的参数、示例数据、绝对路径及运行环境要求需要与平台适配：固定任务模板、阈值、超时、图表主题及章节要求统一放在 egs 下 YAML；密钥和外部数据认证通过项目 .env 引用。只复制任务所需文件，不复制用户凭证、缓存、历史产物、自动安装器和无关组合管理文件，不修改 C 盘原件或任何环境包。

首次运行后不能再依赖 C 盘 WorkBuddy 安装。项目内执行器真正读取 Skill 与引用资料并记录摘要，避免只是登记一个名称后仍使用通用问答提示词。

## 执行链路

| 阶段 | 行为与实际输出 |
| --- | --- |
| 校验与计划 | 验证证券、市场、日期、数据模式和模型/CLI 能力，创建独立任务与报告目录 |
| 加载 Skill | 读取项目内 SKILL 与指定参考，组合 YAML 中固定任务提示词，保存实际任务配置 |
| 采集与计算 | 复用平台行情、新闻、证券和个股服务，必要时接入已配置数据工具；保存实际时点与来源 |
| 研究与写作 | OpenAI 兼容普通生成或已接通的 Codex 只读调用；需工具时采用传统文本 ReAct，不用 function call |
| 证据核对 | 区分原始事实、计算值、模型推断和缺失项；引用必须对应实际来源，结构化结果用 json_repair 解析 |
| 报告构建 | 用项目内模板和实际图表构建 HTML，保存正文、输入摘要、引用及核对结果 |
| 展示与归档 | 在页面内阅读，支持下载及历史重开；失败保留真实原因，不生成成功占位报告 |

现有 SkillManager 主要负责参数契约，无法执行任意安装目录。本次增加明确的内置 Skill 执行映射，复用既有模型/CLI能力与领域数据服务；不开放通用 shell 或任意外部脚本执行。

## 报告内容与数据边界

市场复盘覆盖指数、板块、成交与资金、情绪、新闻政策、海外背景、风险、后续观察及引用。图表按实际数据生成，缺少资金、海外或公众号来源时明确缺失，不能为了满足原 Skill 的图数要求伪造数据或宣称完整通过。

个股报告覆盖证券身份、价格与量能、趋势/动量/波动、基本面与估值、相关事件、风险及观察清单。采用 stock-analysis 的研究维度并结合 A 股技术参考；筹码、主力资金、机构观点或专门指标没有真实输入时不由语言模型猜数，不宣称全部 23 项指标已经实现。

默认使用平台已选市场与数据模式；mock 结果必须显式标为演示，真实数据与真实模型分别验证。底层尚不支持的市场或数据项如实说明。neodata/公众号等认证依赖通过现有集成和 .env 可选接入，不读取 WorkBuddy 的私人 token 缓存。

报告以 HTML 为本次交付格式，不扩展到 PPT、视频、社交发布或自动交易。原 Skill 的多模态门禁不能直接用于宣称本项目的 HTML 报告全部通过；本项目单独检查 HTML、图表、引用、日期和能力缺失。

## 模块及存储范围

| 位置 | 职责 |
| --- | --- |
| src/skills | 本地 Skill 文本、必要参考、来源及适配说明 |
| src/engine/insights | Skill 加载、任务执行、证据与 HTML 报告构建，按职责拆分 |
| egs 下智能洞察 YAML | 固定提示词、任务预设、模型选择、限制与展示参数 |
| src/frontend/features/insights.py | 左侧快捷任务、必要输入与右侧报告预览，避免继续扩展现有大文件 |
| src/frontend/service/insights.py | 回调适配和真实阶段更新 |
| src/api/routes 下洞察接口 | 报告任务、结果与历史文件访问，按精确标识访问项目产物 |
| data/reports/insights | 独立任务的 HTML、正文、图表、来源和配置摘要 |
| tests/engine、tests/api、tests/frontend | 执行、文件访问、回调和页面集成验证 |

HTML 采用受控模板，内嵌展示隔离报告脚本与工作台；图表和下载路径限定于本任务目录。长任务按实际阶段更新，不阻塞页面进入或重复提交同一运行。使用 Windows/Linux 通用路径和项目 Python 环境。

## 开发与验收

1. 复制并登记所需 Skill 资源，完成 YAML 配置和本地执行映射。
2. 跑通市场复盘与个股报告服务，再接左侧按钮、状态、历史和 HTML 预览。
3. 单元测试覆盖提示词加载、日期、来源缺失、证券错误、JSON 修复、报告构建和任务隔离；集成核对 HTML 文件、引用、图表和持久结果。
4. 浏览器模拟点击两个任务，核对阶段、重复点击、失败提示、报告显示、历史重开和下载，并保存截图。
5. 真实数据及真实模型/CLI分别记录验证证据；没有可用凭证或外部源时列出实际缺口，不把 mock 或测试替身算作真实报告通过。
6. Review 后运行适用 Ruff、mypy、pytest、pip-audit、Bandit 等检查；工具缺失如实记录。核对首屏及生成耗时，不在进入智能洞察时自动运行重任务。
7. 同步使用文档和原理文档、MkDocs 导航、设计及 changelog。停止测试服务，临时文件按用户规则取得清理确认。
