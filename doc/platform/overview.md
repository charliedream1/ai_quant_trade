# AIQuant智投 一体化量化交易平台 - 总体设计文档

## 1. 项目概述

### 1.1 项目定位

AIQuant智投 是一个 AI 驱动、面向 A 股个人投资者的**"研读 - 构建 - 仿真 - 实盘"一体化量化交易平台**。平台以市场分析为起点、以策略为核心资产、以仿真为安全垫、以实盘为最终出口，将个人投资者原本分散在多个工具（看盘软件、新闻网站、回测框架、笔记软件）中的工作流，收敛到同一个可长期运营的系统内。

本平台是 a001_news_track（行业温度计）的第二个升级版本：信息研读能力（新闻、行情、个股分析）继承并深化，交易执行能力（策略、仿真、实盘）全新构建。

### 1.2 目标用户

| 用户画像 | 典型需求 |
|----------|----------|
| A 股个人投资者 | 每日快速了解市场全景与个股详情，希望把研究结论沉淀为可重复执行的策略 |
| 量化爱好者 | 希望低成本完成"写策略 → 回测 → 模拟 → 小资金实盘"的完整验证链路 |
| 独立研究员 | 需要论文、研报、笔记的统一知识管理与大模型问答辅助 |

共性特征：具备一定编程与研究能力，但缺少机构级数据与交易基础设施，对部署成本与大模型调用成本敏感。

### 1.3 核心价值

- **一体化闭环**：市场分析 → 策略构建 → 仿真 → 实盘在同一平台完成，研究结论可直接转化为策略并验证落地，无需在多个工具间手工搬运。
- **AI 全链路融入**：新闻解读、股票推荐（小模型快速过滤 + 大模型精选）、策略辅助生成（CLI 集成）、知识库问答均由 AI 驱动，且传统算法兜底。
- **成本可控**：以免费公开数据源为主，大模型按需调用、多模型分级（快速模型做过滤、深度模型做推荐），本地 SQLite 零运维。
- **个人可部署**：单机单进程即可长期运行，适合个人电脑、家用服务器或 NAS。

### 1.4 设计原则

| 原则 | 含义 | 落地手段 |
|------|------|----------|
| 成本可控 | 默认走低成本路径，AI 能力按需启用 | 传统算法（jieba TF-IDF、形态过滤、小模型）兜底；LLM 调用分级管理；结果缓存复用 |
| 稳定优先 | 单点失败不影响整体可用性 | 多源数据 fallback 与失败冷却；实盘前强制经过回测与模拟盘；LLM 不可用时自动降级 |
| 渐进增强 | 从基础能力到深度能力分层提供 | 基础行情 → 消息分析 → 智能推荐 → 策略仿真 → 实盘，逐级开放、逐级验证 |
| 一体化闭环 | 研读-构建-仿真-实盘全链路数据打通 | 统一数据底座、统一策略接口、统一任务调度、统一实时推送通道 |

## 2. 与 a001_news_track 的差异与复用

### 2.1 总体关系

a001_news_track 验证了"多源数据采集 + 双模式分析 + 个人可部署"的可行性。本平台**复用其数据采集与分析引擎的思路**（按新架构重写整合，非直接搬运代码），**功能整体重构扩展**为七大模块。当前默认前端采用 Gradio-first 模块化多应用架构，各业务域独立挂载到 `/app/<module>/` 并按首次访问延迟构建，与 FastAPI 单进程交付；Jinja2 双前端和 Vue SPA 均不作为当前实现目标。

### 2.2 复用清单

| 复用项 | 在 a001_news_track 中的形态 | 在本平台中的落位 |
|--------|------------------------------|------------------|
| 多源数据 fallback 机制 | 数据源管理器按优先级自动切换 + 失败源冷却 | 数据层通用机制，扩展覆盖行情/新闻/研报/论文四类数据 |
| AKShare 数据源 | akshare_source 封装（行情/板块/基本面） | 数据层主数据源之一 |
| 东方财富 push2 数据源 | 直接 HTTP 接口封装（实时行情/K线） | 数据层实时行情备源 |
| BaoStock 数据源 | 历史 K 线数据封装 | 数据层历史行情补源（回测数据基础） |
| 新闻分析双模式 | jieba TF-IDF（传统、零成本）+ LLM（深度） | 引擎层消息分析能力，覆盖国内/国外/财经/公司四类新闻 |
| 热力图/趋势/风险/个股分析引擎思路 | 四大分析器的评分体系与阈值规则 | 引擎层市场分析引擎重构升级，并入市场分析模块 |
| SQLite + FTS5 存储模式 | 全文检索虚拟表 + 触发器同步 + LIKE 兜底 | 核心层存储管理，支撑知识库/策略库/研报/论文的检索 |
| loguru / 配置三级管理核心层 | YAML + 环境变量 + 默认值三级配置、结构化日志 | 核心层直接沿用思路并扩展（新增 LLM 多模型、MCP 等配置项） |

### 2.3 新增能力清单

| 新增能力 | 说明 |
|----------|------|
| 策略全生命周期管理 | 策略库存储/上传策略代码、自研策略统一接口接入、策略版本与参数管理 |
| 回测/模拟盘/实盘引擎 | 历史数据回测与绩效评估、paper trading 模拟撮合、实盘执行与监控 |
| CLI 集成 | 以子进程方式调用 trae cli / workbuddy cli / codex cli，AI 辅助生成策略代码并自动入库 |
| MCP/Skill 集成 | MCP 服务配置与连接管理、Skill 注册与调用 |
| 远程知识库 | 经 MCP 协议连接操控飞书文档、腾讯 ima，与本地知识库统一检索入口 |
| 定时任务中心 | cron 风格定时执行（分析/回测/模拟盘/数据更新）、执行历史、启停控制 |
| 模块化 Gradio 主界面 | 九个 `/app/<module>/` 独立应用覆盖总览、市场、研报、策略、仿真、实盘、AI、知识库和系统管理，按业务域延迟构建 |
| Gradio 迁移对照入口 | `/legacy-app/` 暂时保留完整单体页面用于功能核对，不作为默认产品入口 |
| WebSocket 实时推送 | 行情刷新、回测进度、模拟盘/实盘状态、任务执行状态实时推送 |
| 量化论文搜索 | 接入论文数据源，检索最新量化研究并纳入知识库 |
| 关联关系图 | 个股/板块/产业链/股东关联的可视化关系图 |
| 股票推荐双层过滤 | 形态识别与小模型快速过滤初筛 + 大模型深度推荐精选 |
| 券商适配器（预留） | 实盘交易通道的标准化适配接口预留，默认以模拟盘运行 |

## 3. 总体架构

### 3.1 架构总览

系统采用"模块化 Gradio 主界面 + FastAPI 后端八大分层 + 底层存储"的总体架构：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                前端层（九个 /app/<module>/ Gradio 应用）                  │
│ 看板 │ 市场 │ 研报 │ 策略 │ 仿真 │ 实盘 │ AI │ 知识库 │ 系统管理 │
│       独立 Blocks │ URL 导航 │ 延迟构建 │ Pandas/Plotly │ 少量 JS       │
└────────────────┬────────────────────────────────────────┬───────────────┘
                 │  REST API（HTTP 请求/响应）             │  WebSocket（实时推送）
┌────────────────▼────────────────────────────────────────▼───────────────┐
│                        API 层（FastAPI）                                  │
│      REST 路由（按七大模块分组） │ WebSocket 端点 │ 前端静态资源托管      │
├───────────────────────────────────────────────────────────────────────────┤
│  智能层：LLM 多模型接口（OpenAI 兼容） │ Agent（分析/推荐/策略生成）      │
├───────────────────────────────────────────────────────────────────────────┤
│  引擎层：市场分析引擎 │ 选股引擎 │ 回测引擎 │ 模拟盘引擎 │ 实盘引擎       │
├───────────────────────────────────────────────────────────────────────────┤
│  策略层：策略库 │ 统一策略接口 │ CLI 构建器（trae cli / workbuddy cli / codex cli）  │
├───────────────────────────────────────────────────────────────────────────┤
│  任务层：APScheduler 定时调度 │ 执行历史 │ 任务启停控制                   │
├───────────────────────────────────────────────────────────────────────────┤
│  集成层：MCP 服务 │ Skill │ 飞书文档 │ 腾讯 ima │ 券商适配器（预留）     │
├───────────────────────────────────────────────────────────────────────────┤
│  数据层：行情数据 │ 新闻数据 │ 研报数据 │ 论文数据（多源 fallback）      │
├───────────────────────────────────────────────────────────────────────────┤
│  核心层：配置管理 │ 日志系统 │ 异常处理 │ 数据缓存 │ 存储管理             │
├───────────────────────────────────────────────────────────────────────────┤
│                          底层存储                                        │
│   SQLite + FTS5（业务数据/全文检索） │ 文件存储（策略代码/笔记/研报 PDF） │
└───────────────────────────────────────────────────────────────────────────┘
```

### 3.2 分层职责说明

| 层次 | 职责 | 关键组成 |
|------|------|----------|
| API 层 | 系统统一出入口 | 七大模块分组的 REST 路由、WebSocket 端点、生产模式静态资源托管、统一异常响应 |
| 智能层 | AI 能力供给 | LLM 多模型接口（OpenAI 兼容、多模型分级）、分析/推荐/策略生成 Agent、Prompt 管理 |
| 引擎层 | 业务计算核心 | 市场分析、选股、回测、模拟盘、实盘五大引擎，各自独立运作 |
| 策略层 | 策略资产管理 | 策略库（存储/上传/版本）、统一策略接口（自研策略接入契约）、CLI 构建器（子进程编排） |
| 任务层 | 周期性调度 | APScheduler 封装、cron 风格任务注册、执行历史记录、启停控制 |
| 集成层 | 外部系统连接 | MCP 客户端与服务配置、Skill 注册、飞书文档与腾讯 ima 适配、券商适配器（预留） |
| 数据层 | 多源数据获取 | 行情/新闻/研报/论文四类数据源、多源 fallback 管理器、数据缓存 |
| 核心层 | 基础设施支撑 | 配置三级管理、loguru 日志、统一异常体系、TTL 缓存、SQLite/FTS5/文件存储管理 |
| 底层存储 | 持久化 | SQLite 数据库与 FTS5 全文索引；文件存储承载策略代码、个人笔记、研报 PDF |

### 3.3 关键数据流

| 数据流 | 路径说明 |
|--------|----------|
| 研读流 | 前端请求 → API 层 → 数据层（多源 fallback）→ 引擎层（市场分析/消息分析）→ 智能层（按需 LLM 增强）→ 返回前端 |
| 策略构建流 | 前端提交需求 → API 层 → 策略层（CLI 构建器子进程调用 trae/workbuddy/codex cli）→ 生成策略代码 → 校验统一接口 → 入策略库 |
| 仿真流 | 前端选择策略与参数 → 引擎层回测引擎/模拟盘引擎 → 数据层历史/实时数据 → 绩效评估结果入库 → WebSocket 推送进度 |
| 实盘流 | 前端配置并启动 → 引擎层实盘引擎加载策略 → 集成层券商适配器（预留，当前走模拟通道）→ 状态经 WebSocket 实时推送 |
| 任务流 | 任务层按 cron 触发 → 调用引擎层/数据层能力 → 执行历史入库 → WebSocket 推送执行状态 |

## 4. 模块划分

七大功能模块与后端分层的映射关系如下：

| 功能模块 | 核心能力 | 主要依托后端层次 |
|----------|----------|------------------|
| 市场分析 | 新闻消息（四类）、行情看盘（通用+个性化）、关联关系图、个股详情、股票推荐（双层过滤）、研报查看、模型市场分析、量化论文搜索 | 数据层、引擎层（市场分析/选股）、智能层、API 层 |
| 策略构建 | 策略库存放/上传、CLI 辅助生成、自研策略统一接口接入 | 策略层、智能层、集成层（CLI 子进程）、核心层（文件存储） |
| 策略仿真 | 模拟回测（选策略与参数）、实盘模拟（paper trading） | 引擎层（回测/模拟盘）、策略层、数据层、任务层 |
| 实盘 | 选择策略、配置实盘、启停与监控 | 引擎层（实盘）、策略层、集成层（券商适配器预留）、任务层、API 层（WebSocket） |
| 知识库 | 本地知识库（分类管理/大模型问答）、远程知识库（飞书/腾讯 ima） | 核心层（存储/FTS5）、智能层（问答）、集成层（MCP）、数据层（研报/论文） |
| 定时任务 | cron 风格定时执行、执行历史、启停控制 | 任务层、引擎层、数据层、API 层（WebSocket 状态推送） |
| 模型配置 | 系统设置、LLM 多模型管理、MCP 服务配置、Skill 配置 | 核心层（配置管理）、智能层（LLM 管理）、集成层（MCP/Skill） |

## 5. 技术选型

| 类别 | 选型 | 选择理由 |
|------|------|----------|
| 前端框架 | Gradio Blocks 4.44-6.x + FastAPI | 九个独立 Gradio 应用与 Python 后端同进程开发和交付，避免全站集中在单个 Blocks |
| UI 呈现 | Gradio 组件 + Plotly/Pandas + 自定义 CSS/JS | 表格、表单、图表、上传和 Chatbot 使用统一组件体系；一级导航使用稳定 URL |
| 图表库 | Plotly | 当前复杂图表仍由 Gradio 前端渲染 Plotly Figure，用于 K 线、净值、板块排行、关系图谱等交互图 |
| 前端状态 | Gradio 回调 + 稳定业务键 + 浏览器 localStorage | 模块间不共享组件对象或 `gr.State`；服务端回调直接调用领域服务，浏览器只保存轻量展示状态 |
| 后端框架 | Python 3.10+ / FastAPI / uvicorn | 异步支持契合行情拉取与 WebSocket 推送；自动生成接口文档；与 a001_news_track 技术栈一致，思路复用成本低 |
| 数据库 | SQLite + FTS5 | 单文件零运维、嵌入式部署；FTS5 提供全文检索支撑知识库/策略库搜索，已在参考项目验证 |
| 定时任务 | APScheduler | 进程内 cron 风格调度，无需引入额外中间件（如消息队列/独立调度器），符合单进程部署原则 |
| 日志 | loguru | 开箱即用、结构化输出、文件轮转，参考项目已验证，降低维护成本 |
| 大模型接入 | OpenAI 兼容接口 | 一套接口规范适配多家模型（DeepSeek/Qwen/GLM 等），支持多模型分级：快速模型做初筛、深度模型做推荐与问答 |
| 实时通信 | WebSocket | 行情刷新、回测进度、模拟盘/实盘状态、任务执行状态需要服务端主动推送，轮询方式延迟高且浪费资源 |
| 策略构建集成 | trae cli / workbuddy cli / codex cli 子进程调用 | 复用成熟的 AI 编码助手生成策略代码；平台侧只做进程编排、产物校验与入库，边界清晰 |
| 远程知识库 | MCP 协议 | 标准化协议连接飞书文档、腾讯 ima 等外部系统，避免为每个平台单独开发适配逻辑，可扩展新源 |

## 6. 规划目录结构

### 6.1 项目根目录

```
AIQuant智投/
├── src/            后端源代码（八大分层）

├── doc/            设计文档（本目录，共 5 份）
├── egs/            样例配置与运行入口
├── data/           运行时数据（SQLite 数据库与文件存储）

```

### 6.2 后端 src/ 目录规划

```
src/
├── core/           核心层 —— 配置三级管理、loguru 日志、统一异常体系、TTL 缓存、存储管理（SQLite/FTS5/文件存储）
├── data/           数据层 —— 行情/新闻/研报/论文多源数据源封装、多源 fallback 管理器、数据源健康状态
├── strategy/       策略层 —— 策略库管理（存储/上传/版本）、统一策略接口定义与校验、CLI 构建器（trae/workbuddy/codex 子进程编排）
├── engine/         引擎层 —— 市场分析引擎、选股引擎（形态/小模型过滤+大模型推荐）、回测引擎、模拟盘引擎、实盘引擎
├── agent/          智能层 —— LLM 多模型接口（OpenAI 兼容）、分析/推荐/策略生成 Agent、Prompt 模板管理
├── scheduler/      任务层 —— APScheduler 封装、任务注册中心、执行历史记录、启停控制
├── integration/    集成层 —— MCP 客户端与服务配置、Skill 注册管理、飞书文档适配、腾讯 ima 适配、券商适配器（预留）
└── api/            API 层 —— FastAPI 应用入口、按七大模块分组的 REST 路由、WebSocket 端点、静态资源托管
```

各目录与总体架构八大分层一一对应；跨层调用约定为"上层可调用下层，下层不得反向依赖"，同层之间通过 API 层或核心层协调。


## 7. 部署形态

### 7.1 开发形态（单进程）

| 组成 | 运行方式 | 说明 |
|------|----------|------|
| 前端 | FastAPI 进程内延迟挂载九个 `/app/<module>/` Gradio 应用 | 无独立前端开发服务器；修改 Python 前端代码后重启或 reload 后端即可 |
| 后端 | uvicorn 启动 FastAPI（默认 8000 端口） | 开启跨域许可；提供 REST API、WebSocket 与自动接口文档 |
| 数据 | 本地 SQLite 主库 + 文件系统文档存储 + Parquet 行情湖 + DuckDB 查询引擎 | 无服务端数据库依赖，适合个人单机长期运行 |

### 7.2 生产形态（单进程一体化部署）

FastAPI 通过独立的延迟 ASGI 包装器挂载九个 Gradio 应用：同一 uvicorn 进程同时提供 REST API、WebSocket 与前端页面，实现**单进程部署**。服务启动不构建 Blocks，首次访问只构建当前模块。若后续另行引入独立 Web 前端，应另开设计文档评审。

| 项目 | 说明 |
|------|------|
| 部署单元 | 单进程（uvicorn 托管 FastAPI 应用） |
| 端口 | 单一对外端口（默认 8000），API 与页面同源 |
| 前端交付 | 根路径 `/` 自动跳转 `/app/` 持久 Gradio 工作台；九个独立模块仍挂载在 `/app/<module>/` 并按需加载，静态资源由 FastAPI 同源提供；主题支持 YAML/环境变量配置的亮色、暗色和系统跟随 |
| 数据 | SQLite 主库、文档文件目录、Parquet 行情湖和 DuckDB 查询库均为本地文件，随项目数据目录管理 |
| 适用环境 | 个人电脑、家用服务器、NAS 等单机长期运行场景 |
| 升级方式 | 替换后端代码与前端构建产物后重启进程 |

### 7.3 部署原则

- **单进程优先**：不引入消息队列、独立调度器等额外中间件，定时任务与 WebSocket 均在应用进程内运行。
- **数据本地化**：系统主库、策略代码、笔记、研报 PDF、Parquet 行情湖和 DuckDB 查询库默认落在项目数据目录，便于备份与迁移。
- **存储分层**：SQLite 负责配置、任务、策略、知识库索引和轻量事务数据；大规模行情、因子和回测面板进入 Parquet，由 DuckDB 做本地分析查询；文档原文由文件系统维护，数据库只保存路径和索引。
- **实盘安全**：实盘引擎默认绑定模拟通道（券商适配器为预留），只有显式配置真实券商通道后才进入真实交易。
