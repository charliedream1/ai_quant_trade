## 1. 后端分层架构

### 1.1 分层总览

后端自上而下分为八层，上层可调用下层，下层不得反向依赖：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        API 层（FastAPI）                                 │
│   REST 路由（按七大模块分组） │ WebSocket 端点 │ 静态资源托管 │ 统一异常  │
├─────────────────────────────────────────────────────────────────────────┤
│  智能层：LLM 多模型接口 │ 分析 Agent │ 推荐 Agent │ 策略生成 Agent       │
├───────────────────────────────┬─────────────────────────────────────────┤
│  引擎层：市场分析 │ 选股推荐 │ 回测 │ 模拟盘 │ 实盘（五大引擎）          │
├───────────────────────────────┴─────────────────────────────────────────┤
│  策略层：策略库 │ 统一策略接口 │ CLI 构建器（trae cli / workbuddy cli / codex cli） │
├─────────────────────────────────────────────────────────────────────────┤
│  任务层：APScheduler 调度 │ 任务注册中心 │ 执行历史 │ 启停控制           │
├─────────────────────────────────────────────────────────────────────────┤
│  集成层：MCP 客户端 │ Skill │ 飞书 │ 腾讯 ima │ 券商适配器（预留）      │
├─────────────────────────────────────────────────────────────────────────┤
│  数据层：行情 │ 新闻 │ 研报 │ 论文（四类数据源 + 多源 fallback 管理器）  │
├─────────────────────────────────────────────────────────────────────────┤
│  核心层：配置管理 │ 日志 │ 异常处理 │ 数据缓存 │ 存储管理               │
├─────────────────────────────────────────────────────────────────────────┤
│  底层存储：SQLite + FTS5 │ 文件存储（策略代码 / 研报 PDF / 笔记）       │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.2 各层职责表

| 层次 | 职责 | 关键组成 | 被谁调用 |
|------|------|----------|----------|
| API 层 | 系统唯一出入口：参数校验、调用编排、统一响应与异常、WebSocket 通道管理 | 七大模块 REST 路由组、WebSocket 端点、静态资源挂载、全局异常中间件 | 前端 / 外部工具 |
| 智能层 | AI 能力供给：LLM 调用封装、多模型分级与热切换、Agent 编排、Prompt 模板管理 | LLM 客户端管理器、分析/推荐/策略生成 Agent、降级策略 | API 层、引擎层、策略层 |
| 引擎层 | 业务计算核心：五大引擎独立运作、互相不直接依赖 | 市场分析引擎、选股推荐引擎、回测引擎、模拟盘引擎、实盘引擎 | API 层、任务层 |
| 策略层 | 策略资产管理：策略存取、版本、校验、AI 辅助生成编排 | 策略库管理器、统一策略接口契约与校验器、CLI 构建器 | API 层、引擎层（加载策略） |
| 任务层 | 周期性调度：cron 任务注册、互斥/超时控制、执行历史 | APScheduler 封装、任务注册中心、执行历史记录器 | API 层（注册/启停），反向调用引擎层/数据层 |
| 集成层 | 外部系统连接：MCP、Skill、远程知识库、券商通道 | MCP 客户端、Skill 注册表、飞书/腾讯 ima 适配、券商适配器（预留） | API 层、智能层、引擎层（实盘） |
| 数据层 | 多源数据获取与统一供给：四类数据源封装、fallback、健康状态、数据落库 | DataSourceManager、AKShare/东方财富 push2/BaoStock/扩展源适配、数据缓存写入 | 引擎层、API 层、任务层 |
| 核心层 | 基础设施：三级配置、结构化日志、统一异常体系、TTL 缓存、SQLite/FTS5/文件存储 | 配置管理、loguru 日志、第三方 stdout 捕获、异常体系、缓存、存储管理器 | 所有层 |

### 1.3 层间调用约定

| 调用方 | 被调方 | 是否允许 | 说明 |
|--------|--------|----------|------|
| API 层 | 智能层/引擎层/策略层/任务层/数据层 | 允许 | 编排入口，按需直调 |
| 引擎层 | 策略层 | 允许 | 回测/模拟/实盘引擎加载并驱动策略 |
| 引擎层 | 数据层、智能层 | 允许 | 取数、按需 LLM 增强 |
| 任务层 | 引擎层、数据层、策略层 | 允许 | 定时触发的执行体 |
| 集成层 | 数据层 | 允许 | 远程文档拉取后走数据落库 |
| 数据层 | 核心层 | 允许 | 缓存与存储 |
| 任意下层 | 任意上层 | 禁止 | 下层通过回调/注入的上下文对象间接协作 |
| 同层之间 | 同层之间 | 禁止直调 | 经 API 层或核心层协调 |

### 1.4 核心数据流

#### 1.4.1 市场分析流

```
前端请求 → API 层（市场分析路由组）
   → 核心层缓存命中? ─ 是 → 直接返回
   → 否 → 引擎层（市场分析/选股引擎）
        → 数据层（行情/新闻/研报多源 fallback 取数）
        → 智能层（按需 LLM 增强，失败自动降级传统算法）
        → 结果写缓存 → API 层 → 前端
```

文字描述：前端发起市场分析类请求（新闻、行情、个股、推荐、研报、论文）；API 层先查核心层 TTL 缓存，未命中则由引擎层组织计算；引擎层向数据层取数（多源 fallback + 失败冷却），需要深度分析时调用智能层 LLM（不可用时降级为传统算法）；结果回写缓存并返回前端。行情看盘类请求额外支持 WebSocket 订阅推送通道（见 2.2）。

#### 1.4.2 策略构建流

```
前端提交构建需求 → API 层 → 策略层（CLI 构建器）
   → 启动 CLI 子进程（trae cli / workbuddy cli / codex cli）
   → stdout 流式解析 → WebSocket 实时回传进度
   → 进程结束 → 扫描产物目录 → 统一策略接口校验链
   → 通过 → 落盘策略库新版本（草稿态，待用户确认）
   → 失败 → 产物暂存 + 失败原因回传
```

文字描述：用户在策略构建工作台提交自然语言需求；CLI 构建器组装"需求 + 统一策略接口契约说明"，以子进程方式调用 trae cli、workbuddy cli 或 codex cli；子进程输出按行流式解析并经 WebSocket 回传；结束后扫描产物，复用策略上传校验链（安全校验→接口校验→参数校验），通过后作为新版本进入策略库（草稿状态），用户确认后转为可用；校验失败则产物进入暂存区，允许人工修正后重新上传。

#### 1.4.3 回测/模拟流

```
前端选择策略与参数 → API 层 → 引擎层（回测引擎 / 模拟盘引擎）
   → 策略层加载策略（统一策略接口）
   → 数据层取历史 K 线（回测）或实时行情（模拟盘）
   → 事件驱动循环：行情注入 → 策略 on_bar/on_tick → 信号
   → 撮合（回测按历史价撮合 / 模拟盘按简化规则撮合）
   → 账户更新 → 净值记录 → WebSocket 推送进度
   → 结束 → 绩效评估 → 报告入库 → 前端查看
```

文字描述：回测引擎与模拟盘引擎共用"驱动策略 → 产生信号 → 撮合 → 更新账户"的主循环骨架；差异仅在数据来源（历史/实时）与撮合规则（见第 4 章）。执行过程中进度（百分比、当前日期、最新净值）经 WebSocket 推送；结束后回测产出绩效报告，模拟盘持续跟踪净值曲线。

#### 1.4.4 实盘流

```
前端配置并启动实盘 → API 层 → 引擎层（实盘引擎）
   → 加载实盘配置 + 策略层加载策略
   → 集成层券商适配器（首期 = 模拟适配器，对接模拟盘引擎）
   → 交易时段内：行情驱动 → 策略信号 → 风控检查（前置）
   → 适配器下单 → 成交回报 → 账户/持仓更新
   → 状态、委托、持仓、风控事件经 WebSocket 实时推送
```

文字描述：实盘引擎按实盘配置运行；每笔信号在下单前必须通过风控检查（第 5.4 节）；执行通道由券商适配器层提供，首期仅注册"模拟适配器"（订单转发给模拟盘引擎撮合），真实券商适配器为预留扩展；所有状态变化经 WebSocket 推送前端监控面板。

#### 1.4.5 知识库问答流

```
用户提问 → API 层（知识库路由组）
   → 本地检索：问题关键词 → 分块 FTS5 优先检索（分块 LIKE 与整篇检索兜底）→ Top K 相关片段
   → 追问补偿：当前问题无命中时读取最近问答上下文，使用上一轮问题回退检索
   → 可选远程检索：集成层 MCP 客户端查飞书 / 腾讯 ima（结果标注来源）
   → 上下文拼装：最近问答 + 资料片段按相关度截断，控制在 LLM 上下文预算内
   → 智能层 LLM 生成（约束"仅依据给定资料回答并标注来源"）
   → 返回答案 + 引用清单 → 问答历史入库
   （LLM 不可用 → 降级返回纯检索片段列表）
```

文字描述：知识库问答采用检索增强生成（RAG）流程，检索范围默认为本地知识库，可配置扩展到远程知识库；最近问答历史用于处理“它/这个/继续”等追问，API 可控制上下文轮数或重置上下文；LLM 生成时限定仅依据检索到的上下文作答并标注来源文档；问答历史落库支持回溯；LLM 不可用时降级为纯检索结果返回。

#### 1.4.6 量化闭环归因流

量化闭环服务吸收 DataAgent 的 SOP 规划、证据工作区、问数和归因建议思想，但不复制外部项目实现。后端以配置化 SOP 为起点，围绕两类流程组织证据：模拟研究闭环覆盖“分析、构建策略、模拟、归因、优化迭代”，真实交易观测闭环覆盖“交易、观测、归因、迭代建议”。

| 阶段 | 输入证据 | 输出 |
|------|----------|------|
| SOP 选择 | 闭环模式、SOP 配置、策略/回测/账户/实盘运行 ID | 统一阶段定义和目标 |
| 证据汇聚 | strategies、backtest_tasks/results、factor 指标与告警、paper 账户与委托持仓、live 配置与订单 | 证据快照 |
| 规则归因 | 绩效、回撤、胜率、因子 RankIC、因子告警、持仓集中度、未完成委托、实盘运行状态 | 归因洞察、严重程度、置信度 |
| 智能问数 | 当前证据、归因洞察、迭代建议 | 面向用户的关键问题与回答 |
| 运行沉淀 | 步骤、产物、上下文、摘要 | quant_workflow_runs、steps、artifacts 记录 |

设计约定：闭环服务优先生成可审计的确定性归因，不依赖 LLM 才能工作；后续接入大模型时，大模型只负责解释、追问和报告润色，结构化归因仍由服务层产出并用 json-repair 解析普通生成结果。

### 1.5 存储分层

系统采用本地轻量存储分层，不引入 Docker 和常驻数据库服务。

| 层次 | 选型 | 责任边界 | 适配场景 |
|------|------|----------|----------|
| 主库 | SQLite + FTS5 | 配置、任务、策略、回测记录、资源池、知识库元数据、问答历史和全文检索索引 | 个人单机、低并发写入、事务型元数据 |
| 文件存储 | 本地文件系统 | 策略代码、文档原文、报告、导出文件和 Qlib/回测产物 | 大文件只存位置，便于备份、迁移和人工查看 |
| 行情湖 | Parquet | 历史行情、因子截面、回测面板、候选池快照等列式数据 | 数据量持续增长、按日期或标的批量扫描 |
| 查询引擎 | DuckDB | 直接查询 Parquet 文件并做本地聚合分析 | 单机 OLAP 分析，无需服务端数据库 |

SQLite 不承担全量行情矩阵的长期分析职责；当行情和因子数据量持续增长时，新增数据优先进入 Parquet，由 DuckDB 查询。只有在多用户远程访问、权限隔离或高并发写入成为明确需求时，再评估 PostgreSQL；只有 tick 级海量扫描和实时聚合成为主需求时，再评估 ClickHouse。Redis 暂不作为默认依赖，短期缓存优先使用进程内 TTL、SQLite 结果表和 Parquet/DuckDB 分层。

## 2. 市场分析模块后端设计

模块总职责：为前端市场分析页面提供四类新闻、行情看盘（通用+个性化）、关联关系图、个股分析、股票推荐、研报与论文的完整数据服务。依托数据层（多源数据）、引擎层（市场分析/选股推荐引擎）、智能层（LLM 按需增强）、API 层（REST + WebSocket）。

### 2.1 新闻服务

**职责**：国内、国外、财经、公司四类新闻的采集、分类、去重、缓存与聚合分析；复用 a001 新闻分析双模式（jieba TF-IDF 传统模式 / LLM 模式）。

| 项目 | 说明 |
|------|------|
| 输入 | 新闻类别、分页参数、股票代码（公司新闻）、分析模式开关（是否用 LLM） |
| 输出 | 分类新闻列表（标题/来源/时间/链接/摘要）、聚合分析结果（关键词、情绪、主题摘要） |
| 依赖 | 数据层新闻数据源（多源 fallback）、核心层缓存与 FTS5 存储、智能层 LLM（可选） |

**数据来源与分类规则表**：

| 新闻类别 | 主要来源 | 备用来源 | 采集方式 | 分类规则 |
|----------|----------|----------|----------|----------|
| 国内新闻 | AKShare 国内财经新闻接口 | 东方财富资讯、新浪财经 | 定时拉取（任务层，盘中高频） | 来源栏目优先，辅以国内媒体关键词词表 |
| 国外新闻 | AKShare 全球财经/华尔街见闻接口 | 东方财富全球频道 | 定时拉取 | 来源栏目 + 外媒关键词词表 |
| 财经消息 | 财联社电报（AKShare 封装） | 东方财富快讯 | 高频定时拉取（盘中分钟级） | 快讯类来源整体归类，辅以"宏观/政策/数据"子标签 |
| 公司新闻 | 东方财富个股资讯（按代码查询） | AKShare 公告接口 | 按需拉取 + 定时增量 | 以涉及股票代码归属（标题/正文实体识别） |

**去重策略表**：

| 规则 | 说明 |
|------|------|
| 主键去重 | 以"来源 + 原文链接哈希"为唯一键，重复拉取直接跳过 |
| 标题相似去重 | 跨源转发检测：标题相似度高于阈值（默认 0.85）视为同一事件，保留最早一条并合并来源 |
| 时间窗 | 去重比较限定在近 48 小时窗口内，避免历史数据全量比对 |

**缓存策略表**：

| 数据 | 缓存键 | TTL | 说明 |
|------|--------|-----|------|
| 分类新闻列表 | 类别 + 页码 | 5 分钟 | 盘中有效，收盘后可延长 |
| 公司新闻 | 股票代码 + 页码 | 10 分钟 | 个股详情页复用 |
| 聚合分析结果 | 类别 + 分析模式 | 30 分钟 | 双模式分别缓存 |

**分析双模式表**（复用 a001，升级覆盖四类新闻）：

| 模式 | 流程 | 输出 | 成本特征 |
|------|------|------|----------|
| 传统模式（默认） | 合并新闻文本 → jieba 分词 + 金融停用词过滤 → TF-IDF 计算词权重 → 行业同义词映射 → 取 Top K 关键词 | 关键词列表、词频统计 | 零成本、秒级 |
| LLM 模式（按需） | 合并新闻文本 → 构造 Prompt（上下文 + 指令）→ 调用 LLM → 解析结构化 JSON | 关键词、主题摘要、情绪倾向、受影响板块 | 走智能层深度模型，失败自动降级传统模式 |

**接口表**：

| 接口 | 方法 | 职责 | 输入 | 输出 |
|------|------|------|------|------|
| /api/market/news | GET | 分页查询四类新闻 | 类别、页码、页大小 | 新闻列表 + 总数 |
| /api/market/news/company/{symbol} | GET | 查询个股公司新闻 | 股票代码、分页参数 | 新闻列表 |
| /api/market/news/analysis | GET | 新闻聚合分析（双模式） | 类别、是否用 LLM | 关键词、摘要、情绪 |

### 2.2 行情服务

**职责**：大盘指数与板块行情供给；通用看盘（预设视图）与个性化看盘（用户自定义关注组合，存 SQLite）；WebSocket 实时/准实时推送。

| 项目 | 说明 |
|------|------|
| 输入 | 指数/板块代码、预设视图标识、用户关注组合 CRUD 请求、WebSocket 订阅消息 |
| 输出 | 指数行情、板块涨跌榜、看盘视图聚合数据、关注组合数据、WebSocket 行情帧 |
| 依赖 | 数据层行情数据源（东方财富 push2 主源 / AKShare 备源）、核心层存储（关注组合表）、API 层 WebSocket 通道 |

**看盘视图设计表**：

| 视图类型 | 内容构成 | 数据来源 | 更新方式 |
|----------|----------|----------|----------|
| 通用看盘-指数盘面 | 上证/深证/创业板/科创50 等核心指数的点位、涨跌幅、成交额 | 数据层指数行情 | WebSocket 准实时推送 |

### 2.5 股票推荐服务（双路径）

**职责**：以"快速过滤初筛 + 大模型精选"双路径生成股票推荐；两路径可独立运行，也可串联（先过滤再 LLM 精选）。

| 项目 | 说明 |
|------|------|
| 输入 | 候选池（全市场 / 指数成分 / 用户组合）、路径选择（仅过滤 / 仅 LLM / 串联）、过滤数量、主题偏好（可选） |
| 输出 | 推荐列表：股票代码、名称、评分、推荐理由、风险提示、路径标识；结果落库支持回看 |
| 依赖 | 引擎层选股推荐引擎、数据层（行情/形态数据）、智能层（LLM 深度模型）、核心层存储（推荐结果表） |

**路径一：快速过滤表**：

| 环节 | 说明 |
|------|------|
| 候选池预处理 | 剔除 ST、*ST、停牌、上市不足 N 日（默认 60 日）个股 |
| 形态识别规则库 | 可配置规则集合：均线多头排列、放量突破 20 日高点、MACD 金叉、缩量回踩均线、N 日新高等；每规则独立开关与参数 |
| 小模型轻量评分 | 以动量、波动率、量比、换手率等低维特征输入本地轻量评分模型，输出 0~100 分（模型文件本地推理，不依赖外部服务） |
| 汇总输出 | 规则命中数 + 小模型分加权排序，取 Top N（默认 30）进入下一环节或直接返回 |

**路径二：大模型推荐表**：

| 环节 | 说明 |
|------|------|
| 输入组装 | 对每个候选标的拼装：个股分析摘要（2.4 输出）、公司新闻情绪、所属板块热度；单标的上下文截断控制 Token |
| 批量调用 | 按批（每批 5~10 只）调用智能层深度模型，要求结构化 JSON 输出 |
| 输出结构 | 股票代码、推荐评级（强/中/弱）、核心逻辑、风险提示、置信度 |
| 降级 | LLM 全部失败时返回路径一结果并标注"未精选" |

**串联流程**（文字描述）：候选池 → 路径一快速过滤（形态规则 + 小模型）→ Top N 候选 → 路径二 LLM 逐批深度分析 → 合并排序生成最终推荐 → 结果写 recommendations 表（含生成时间、路径、入选快照）→ 返回前端。

**接口表**：

| 接口 | 方法 | 职责 | 输入 | 输出 |
|------|------|------|------|------|
| /api/market/recommend | POST | 触发推荐（双路径可选） | 候选池、路径、数量、偏好 | 推荐列表 + 任务标识 |
| /api/market/recommend/history | GET | 推荐历史回看 | 分页参数、日期过滤 | 历史推荐记录 |

## 3. 策略构建模块后端设计

模块总职责：策略资产的存储、上传、版本管理与 AI 辅助生成；自研策略以统一接口接入。依托策略层为主，文件存储与校验依赖核心层，AI 生成依赖集成层 CLI 子进程。

### 3.1 策略库

**职责**：策略代码文件存储（文件系统）+ 元信息入库（SQLite）；策略上传校验与入库；版本管理。

| 项目 | 说明 |
|------|------|
| 输入 | 上传的策略文件（.py / .zip）、策略元信息、版本操作请求 |
| 输出 | 策略列表、策略详情（含版本历史）、版本文件内容、校验报告 |
| 依赖 | 核心层文件存储与 SQLite、统一策略接口校验器 |

**存储结构**（文字描述）：

- 文件系统：data/strategies/{策略名}/{版本号}/ 目录存放该版本全部文件（主文件 + 附带资源），版本目录只写不改。
- 数据库：strategies 表存策略主记录；strategy_versions 表存版本元信息（版本号、文件路径、参数模式、入口文件、校验状态、创建时间）。

**存储设计表**：

| 表 | 关键字段 | 说明 |
|----|----------|------|
| strategies | id、name、description、status（草稿/可用/停用）、current_version、created_at、updated_at | 策略主记录 |
| strategy_versions | id、strategy_id、version、file_path、entry_file、params_schema、uni、checksum、source（上传/CLI 生成）、created_at | 版本记录（不可变）；uni 即统一策略接口元信息中的 universe（标的池声明，见 3.2），随版本固化 |

**上传流程表**（.py/.zip → 校验 → 入库）：

| 步骤 | 处理内容 | 失败处理 |
|------|----------|----------|
| 1. 接收文件 | 校验扩展名（.py/.zip）与大小上限（默认 10MB） | 拒收并返回原因 |
| 2. 解压展开 | .zip 解压至临时目录；校验路径穿越与文件类型白名单 | 拒收 |
| 3. 安全校验 | 危险调用黑名单扫描（系统命令、动态执行、网络后门等模式） | 拒收并列出命中项 |
| 4. 接口校验 | 按统一策略接口契约校验：元信息齐备、生命周期方法存在（见 3.2） | 返回缺项清单 |
| 5. 参数校验 | params 为合法参数定义（名称/类型/默认值/范围） | 返回非法项 |
| 6. 入库落盘 | 文件复制到版本目录、写库、记录 checksum | 事务回滚 |
| 7. 返回报告 | 校验报告（通过/告警项） | — |

**版本管理设计表**：

| 机制 | 说明 |
|------|------|
| 版本号 | 语义化版本（主.次.修订），上传时显式指定或自动递增 |
| 版本不可变 | 已入库版本文件与元信息只读；重新上传生成新版本 |
| 多版本并存 | 同一策略保留全部版本；回测/模拟/实盘配置绑定具体版本 |
| 回滚 | "设为当前版本"仅切换 current_version 指针，不删除历史版本 |

**接口表**：

| 接口 | 方法 | 职责 | 输入 | 输出 |
|------|------|------|------|------|
| /api/strategies | GET/POST | 策略列表 / 登记新策略 | 分页 / 元信息 | 列表 / 新策略 |

### 3.2 统一策略接口约定

**职责**：定义自研策略接入平台的唯一契约；同一策略代码在回测、模拟盘、实盘三种执行环境透明复用。

当前实现采用“标准端口 + 适配器”方案。平台可识别 StrategyBase 标准类、普通类端口和函数端口，并在入库与回测前执行校验和 dry-run 预检。这样可以把人工上传、egs 示例和 trae/workbuddy/codex 等 CLI 产物统一包装成同一运行端口。

**策略元信息约定表**：

| 字段 | 含义 | 约束 |
|------|------|------|
| name | 策略唯一名称 | 英文标识，与策略库主记录一致 |
| version | 策略版本号 | 语义化版本 |
| params | 参数定义集合 | 每参数含名称、类型、默认值、取值范围；供回测/实盘配置页自动生成表单 |
| uni | 标的池（universe）约定 | 显式股票代码列表，或预置池标识（如 HS300、全市场）；执行时可被任务配置覆盖 |
| desc | 策略说明（可选） | 一段文字描述，供策略库展示 |

**生命周期方法约定表**：

| 方法 | 调用时机 | 职责 | 输入 | 输出 |
|------|----------|------|------|------|
| 初始化（on_init） | 引擎加载策略后调用一次 | 读取参数、准备指标与内部状态 | 执行上下文（参数、标的池、环境标识） | 无（异常即视为初始化失败） |
| 每 bar 驱动（on_bar） | 每根 K 线闭合时 | 计算指标、产生交易信号 | 当根 bar 数据、账户快照 | 信号列表（标的/方向/目标仓位或数量） |
| 定时驱动（on_tick，可选） | 模拟盘/实盘盘中按周期触发 | 盘中高频逻辑 | 最新报价快照、账户快照 | 信号列表 |
| 信号生成（generate_signals） | 引擎在 on_bar/on_tick 后统一调用 | 汇集并规整待执行信号 | 策略内部信号缓冲 | 规整后的信号列表 |
| 风控钩子（on_risk_check） | 信号提交后、下单前 | 策略级自检（仓位/频率/自定义约束） | 待执行信号、账户状态 | 放行 / 拒绝及原因 |
| 销毁（on_stop） | 回测结束、模拟/实盘停止时 | 落盘策略内部状态、清理资源 | 无 | 无 |

**执行环境透明设计表**：

| 设计点 | 说明 |
|--------|------|
| 统一上下文注入 | 策略只面对引擎注入的上下文对象：行情馈送（历史回放或实时流）、账户接口（查询/下单）、日志接口；三种环境各注入不同实现 |
| 环境无感知 | 策略代码不区分回测/模拟/实盘；环境差异（撮合方式、费率、行情时点）全部由引擎侧承担 |
| 信号统一 | 三种环境产出的信号结构一致，均经风控检查后进入各自撮合通道 |
| 校验器复用 | 上传校验与 CLI 产物校验使用同一契约校验器，保证三入口（上传/CLI/自研）策略规格一致 |
| 适配器隔离 | 不同代码形态先由策略层适配为统一端口，再交给回测、模拟盘和实盘引擎 |
| 预检前置 | 策略详情和回测创建会执行 dry-run，提前暴露入口缺失、参数不匹配或信号格式问题 |

### 3.3 CLI 构建器

**职责**：以子进程方式编排 trae cli / workbuddy cli / codex cli，AI 辅助生成策略代码；流式回传构建过程；产物校验后落盘策略库。

| 项目 | 说明 |
|------|------|
| 输入 | 构建任务（自然语言需求、目标标的、周期、参数期望）、CLI 选择、超时配置 |
| 输出 | 构建任务状态与流式日志（WebSocket）、生成的策略文件、入库结果 |
| 依赖 | 集成层 CLI 子进程管理、策略层校验器与策略库、API 层 WebSocket、核心层配置（CLI 路径与超时） |

**子进程调用方式表**：

| 项 | 约定 |
|----|------|
| CLI 类型 | trae cli、workbuddy cli、codex cli 多选一，配置于系统设置（可执行路径、默认参数模板） |
| 任务提交 | 组装"用户需求 + 统一策略接口契约说明 + 输出目录约定"，以命令行参数与临时任务文件传入子进程 |
| 工作目录 | 每次构建独立临时工作目录，隔离产物与中间文件 |

**构建流程**（文字描述）：① 用户在策略构建工作台填写需求并提交 → ② 平台生成构建任务（排队中）→ ③ 获取并发额度后启动 CLI 子进程（运行中），超时计时开始 → ④ 流式回传日志 → ⑤ 进程结束后扫描产物 → ⑥ 复用上传校验链（安全→接口→参数）→ ⑦ 校验通过则以"草稿"版本落盘策略库，推送"待确认"状态；校验失败则产物移入暂存区并回传失败原因 → ⑧ 用户在工作台预览代码，可选择"确认入库（转可用）"、"修改需求重新生成"或"放弃"。

**超时与失败处理表**：

| 场景 | 处理 |
|------|------|
| 超时（默认 30 分钟，可配置） | 强制终止子进程 → 任务标记失败 → 保留已产出日志供查看 |
| 非零退出 | 记录退出码与末尾日志 → 任务标记失败 |
| 产物缺失 | 任务标记"生成失败（无产物）" |
| 产物校验未通过 | 任务标记"生成成功、校验未过"；产物暂存，允许下载修正后走上传流程入库 |
| 并发控制 | 同时运行 CLI 构建任务上限默认 1，超出的任务排队 |

**接口表**：

| 接口 | 方法 | 职责 | 输入 | 输出 |
|------|------|------|------|------|
| /api/strategy-builder/tasks | POST/GET | 提交构建任务 / 任务列表 | 需求描述、CLI 类型、策略名 | 任务标识 / 列表 |
| /api/strategy-builder/tasks/{id} | GET/DELETE | 任务详情（含日志） / 取消任务 | 任务 id | 详情 / 操作结果 |
| /api/strategy-builder/tasks/{id}/confirm | POST | 确认草稿入库（转可用） | 任务 id | 版本记录 |

## 4. 策略仿真模块后端设计

模块总职责：历史数据回测与绩效评估；paper trading 模拟盘。依托引擎层回测/模拟盘引擎、策略层策略加载、数据层行情数据、任务层例行调度。

### 4.1 回测引擎

**职责**：按任务配置在历史数据上事件驱动地执行策略，产出绩效报告。

| 项目 | 说明 |
|------|------|
| 输入 | 回测任务（策略+版本、区间、初始资金、费率、复权方式、标的池、基准、滑点） |
| 输出 | 回测报告：绩效指标、净值曲线、成交明细、持仓变化、进度推送 |
| 依赖 | 策略层（策略加载）、数据层（历史 K 线，BaoStock 主源 / AKShare 补源）、核心层存储、API 层 WebSocket |

当前实现引入回测引擎注册层。`simple` 是内置轻量日 K 事件回测引擎，会加载策略标准端口、读取可用 K 线、逐 bar 调用 `on_bar`，按 long/flat、佣金和滑点生成资金曲线、基准、回撤、绩效指标和交易明细；它用于页面流程、策略端口回归和首版离线仿真，不承担机构级组合约束。`qlib` 是可选投研引擎入口，用于连接 Qlib workflow、因子/模型训练和组合回测。API 和前端只依赖统一 Runner，不直接依赖具体第三方库；当 qlib 环境或 workflow 未配置时，系统返回明确的配置依赖错误，不将 simple 结果伪装成 qlib 结果。`QlibWorkflowService` 负责读取 `egs/config/models/qlib.yaml` 或示例配置、诊断环境并向 `qlib_runs` 写入 workflow/backtest/factor 运行记录；当 pyqlib、provider_uri、workflow YAML 和 `qrun` 命令均就绪时调用 Qlib 原生 `qrun`，回填 running/finished/failed/blocked 状态、返回码、执行耗时、输出尾部和失败原因。

**回测任务模型表**：

| 字段 | 说明 | 默认值 |
|------|------|--------|
| strategy_id + version | 回测的策略与版本 | 必填 |
| engine | 回测引擎标识 | simple |
| 回测区间 | 开始日期、结束日期 | 必填 |
| 初始资金 | 虚拟账户起始现金 | 1,000,000 |
| 费率 | 佣金费率、印花税率 | 佣金万 2.5、印花税千 1（卖出） |
| 复权方式 | 前复权 / 后复权 / 不复权 | 前复权 |
| 标的池 | 覆盖策略元信息 uni 或另行指定 | 用元信息 |
| 基准 | 对比指数 | 沪深 300 |
| 滑点 | 简化滑点比例 | 0.1% |

**事件驱动回测循环**（文字描述）：

1. 预加载：按区间与标的池从数据层取历史 K 线（统一复权处理），构建时间轴对齐的行情事件序列。
2. 初始化：创建回测上下文与虚拟账户，加载策略并调用初始化方法。
3. 主循环：沿时间轴逐 bar 推进——
   - 注入当 bar 行情（含截止当 bar 的历史窗口）；
   - 调用策略 on_bar，收集信号；
   - 调用信号生成规整与策略风控钩子；
   - 撮合：默认按当 bar 收盘价（可配置为次 bar 开盘价）加减滑点模拟成交，扣除费率；
   - 更新虚拟账户（现金/持仓），记录净值点与成交明细；
   - 按步长（如每日或每 1%）经 WebSocket 推送进度（百分比、当前日期、最新净值）。
4. 收尾：循环结束调用策略销毁方法 → 计算绩效指标 → 报告入 backtest_reports 表 → 推送完成状态。

**绩效指标计算表**：

| 指标 | 定义 |
|------|------|
| 总收益率 | （期末净值 − 初始资金）/ 初始资金 |
| 年化收益率 | 按区间交易日数折算的复合年化 |
| 最大回撤 | 净值曲线峰谷最大跌幅（含区间与持续天数） |
| 夏普比率 | 超额收益 / 收益波动率（无风险利率默认 2%） |
| 索提诺比率 | 超额收益 / 下行波动率 |
| Calmar 比率 | 年化收益率 / 最大回撤 |
| 胜率 | 盈利平仓笔数 / 总平仓笔数 |
| 盈亏比 | 平均单笔盈利 / 平均单笔亏损 |
| 交易统计 | 交易次数、平均持仓周期、换手率 |
| 基准对比 | 区间基准收益率、超额收益 |

**接口表**：

| 接口 | 方法 | 职责 | 输入 | 输出 |
|------|------|------|------|------|
| /api/backtest/tasks | POST/GET | 创建回测任务 / 任务列表 | 任务模型字段 | 任务标识 / 列表 |
| /api/backtest/tasks/{id} | GET/DELETE | 任务详情与进度 / 取消 | 任务 id | 状态、进度、报告 |
| /api/backtest/tasks/{id}/report | GET | 回测报告 | 任务 id | 指标、净值曲线、成交明细 |
| /ws/backtest/{id} | WS | 回测进度推送 | 任务 id | 进度帧 |

### 4.2 模拟盘引擎（paper trading）

**职责**：以实时行情驱动策略的模拟交易：模拟账户、模拟撮合、订单状态机、净值曲线跟踪。

| 项目 | 说明 |
|------|------|
| 输入 | 模拟盘配置（策略+版本、初始资金、标的池、驱动周期）、实时行情流 |
| 输出 | 账户资金与持仓、委托与成交记录、净值曲线、状态推送 |
| 依赖 | 数据层实时行情、策略层、任务层（开盘前/盘中/收盘后例行）、核心层存储 |

**模拟账户存储设计表**：

| 表 | 关键字段 | 说明 |
|----|----------|------|
| paper_accounts | id、config_id、cash_total、cash_available、cash_frozen | 模拟资金账户 |
| paper_positions | account_id、symbol、quantity、available、cost_price | 模拟持仓（含可卖数量，T+1 简化处理） |
| paper_orders | account_id、symbol、direction、order_type、price、quantity、filled_quantity、status、created_at、updated_at | 委托单（状态机字段） |
| paper_trades | order_id、symbol、direction、price、quantity、fee、traded_at | 成交明细 |
| paper_equity_snapshots | account_id、total_equity、cash、market_value、snapshot_at | 净值快照（盘中周期 + 收盘定例） |

**模拟撮合规则表**（以实时行情按简化规则撮合）：

| 规则 | 说明 |
|------|------|
| 市价单 | 以最新成交价立即全额成交 |
| 限价单 | 最新价触及限价即成交（买单：最新价 ≤ 限价；卖单：最新价 ≥ 限价） |
| 成交数量 | 简化模型默认触及即全额成交；可选"按标的成交量比例部分成交"模式 |
| 涨跌停限制 | 委托价或最新价触及涨跌停时不成交，委托保持待成交 |
| 资金与持仓校验 | 买入前校验可用资金、卖出前校验可卖持仓，不足直接拒单（状态=已拒绝） |
| 费用 | 成交时按配置费率扣减佣金与印花税 |

**订单状态机**：

```
              提交且校验通过
   ┌────────┐ ─────────────→ ┌────────┐  部分成交   ┌──────────┐
   │ 已拒绝  │                │ 待成交  │ ─────────→ │ 部分成交  │
   └────────┘ ←─校验失败─  └───┬────┘             └────┬─────┘
                              │ 全部成交                │全部成交
                    ┌─────────┼────────────┐           │
                    │撤单     │全部成交     │撤单        ▼
                    ▼         ▼            ▼      ┌────────┐
               ┌────────┐ ┌────────┐ ┌────────┐   │ 已成交  │
               │ 已撤单  │ │ 已成交  │ │ 已撤单  │   └────────┘
               └────────┘ └────────┘ └────────┘
```

状态集合：已拒绝、待成交、部分成交、已成交、已撤单；其中已成交/已撤单/已拒绝为终态。

**净值曲线跟踪表**：

| 环节 | 说明 |
|------|------|
| 盘中快照 | 按行情驱动周期（如每 5 分钟）计算总权益（现金 + 持仓市值）并快照 |
| 收盘定例 | 收盘后按收盘价重估持仓，写入当日收盘快照（任务层例行触发） |
| 曲线输出 | 快照序列输出给前端绘制净值曲线；支持按日/按盘中粒度切换 |

**接口表**：

| 接口 | 方法 | 职责 | 输入 | 输出 |

| /api/paper/configs | POST/GET | 创建 / 列出模拟盘配置 | 策略、资金、标的池、周期 | 配置记录 |
| /api/paper/configs/{id} | PUT/DELETE | 修改 / 删除配置 | 配置 id | 操作结果 |
| /api/paper/configs/{id}/start | POST | 启动模拟盘 | 配置 id | 运行状态 |
| /api/paper/configs/{id}/stop | POST | 停止模拟盘 | 配置 id | 运行状态 |
| /api/paper/accounts/{id} | GET | 账户资金与持仓 | 账户 id | 资金、持仓列表 |
| /api/paper/accounts/{id}/orders | GET | 委托与成交记录 | 账户 id、状态过滤 | 委托/成交列表 |
| /api/paper/accounts/{id}/equity | GET | 净值曲线 | 账户 id、粒度 | 快照序列 |

## 5. 实盘模块后端设计

模块总职责：实盘配置管理、实盘运行器、券商适配器层（预留）、前置风控检查、WebSocket 状态推送。首期不绑定真实券商，以模拟适配器对接模拟盘引擎完成全流程验证。

### 5.1 实盘配置

**职责**：定义一个实盘运行实例的全部要素。

**实盘配置项表**：

| 配置项 | 说明 | 约束 |
|--------|------|------|
| 策略 + 版本 | 实盘运行的策略 | 必须为"可用"状态版本 |
| 标的池 | 覆盖策略 uni 或显式指定 | 非空 |

### 5.2 实盘运行器

**职责**：加载实盘配置与策略，在运行时段内驱动策略、执行风控、经适配器下单，并维护运行状态机。

**运行状态机**：

```
                 启动                暂停
   ┌────────┐ ───────→ ┌────────┐ ───────→ ┌────────┐
   │ 已创建  │          │ 运行中  │ ←─────── │ 已暂停  │
   └────┬───┘          └──┬──┬──┘   恢复    └───┬────┘
        │ 启动             │  │停止              │停止
        │                 │  └────────┐         │
        ▼                 ▼           ▼         ▼
                      ┌────────┐ ┌──────────────────┐
                      │ 已停止  │ │      异常         │
                      └────────┘ └────────┬─────────┘
                                          │ 人工处置
                            重新运行 / 停止 ↓
                                  回到 运行中 / 已停止
```

**状态迁移表**：

| 操作 | 前置状态 | 后置状态 | 动作 |
|------|----------|----------|------|
| 启动 | 已创建 / 已暂停 | 运行中 | 校验配置与适配器连接，加载策略并初始化 |
| 暂停 | 运行中 | 已暂停 | 停止信号执行，保留账户与策略状态 |
| 恢复 | 已暂停 | 运行中 | 恢复行情驱动（策略状态延续） |
| 停止 | 运行中 / 已暂停 / 异常 | 已停止 | 调用策略销毁，落盘运行摘要；可选"撤除全部未成交委托" |
| 异常进入 | 运行中 | 异常 | 捕获不可恢复错误（策略崩溃/适配器断连），冻结下单，推送告警 |
| 异常处置 | 异常 | 运行中 / 已停止 | 人工确认后恢复或停止 |

当前首版落地 `starting/running/paused/stopping/stopped/error` 六态，已实现启动、暂停、恢复、停止、人工异常冻结、通道异常事件冻结、运行时长、中文标签、重复启动拦截、非法迁移拦截和终态重复停止拦截；真实券商下单和回报对账仍作为后续实盘适配阶段补齐。

**运行器主循环**（文字描述）：交易时段内按驱动周期获取实时行情 → 注入策略（on_tick / 周期性 on_bar 闭合）→ 收集信号 → 前置风控检查（5.4）→ 通过者经适配器下单 → 接收成交回报更新账户与持仓 → 状态与事件推送 WebSocket。盘中触发熔断或收盘后按配置自动进入暂停/停止。

## 7. 定时任务模块后端设计

模块总职责：APScheduler 进程内调度、任务类型管理、cron 配置、执行历史与重试、任务互斥与超时控制。依托任务层，执行体落在引擎层/数据层/策略层。当前实现已接入应用生命周期后台调度，优先使用 APScheduler；运行环境缺少 APScheduler 时使用内置线程轮询 `scheduled_jobs.next_run_at` 兜底，避免服务启动失败；cron 触发支持按任务参数启用交易日过滤、交易日历文件、失败重试、超时标记和 notify 推送。

### 7.1 调度器设计

| 设计项 | 约定 |
|--------|------|
| 调度器 | APScheduler 进程内后台调度（应用启动时创建，随应用生命周期管理）；缺包时降级为内置线程轮询 |
| 任务注册中心 | 启动时从 scheduled_jobs 表装载启用的任务并注册；增删改经 API 操作后热生效（无需重启） |
| 手动控制 | 支持单个任务启停、手动触发一次（不改变 cron 计划），执行结果写入 job_executions |
| 触发器 | cron 触发器为主；可选间隔触发（简单周期任务） |
| 交易日历 | 每任务可开启"仅交易日执行"过滤；默认使用周末过滤，可通过全局 `trading_calendar_path` 或任务级 `calendar_path/trading_calendar_path` 读取 YAML 日历文件，并通过 `trading_calendar.holidays/extra_trading_days` 参数覆盖节假日和补班交易日；`calendar_refresh` 可从 AKShare/Sina 自动生成项目内 YAML 日历；`calendar_reference_refresh` 可将人工整理日期或公告文本、项目内公告文件、指定公告 URL、公告列表页关键词发现结果、项目内交易所公告源 profile 保守解析出的节假日和周末开市日写入官方参考 YAML；`calendar_announcement_profile_check` 只读核验 profile 文件、公告列表页可达性和关键词命中情况；`system_health_check` 会检查日历缺失、解析异常、过期、即将过期和更新时间偏久，若配置 `official_calendar_path` 会对比官方参考 YAML 并推送差异告警 |

内置执行体覆盖 `news_fetch`、`market_refresh`、`recommend`、`report`、`backtest`、`paper_check`、`calendar_refresh`、`calendar_reference_refresh`、`calendar_announcement_profile_check`、`system_health_check`、`data_maintain` 和 `kb_sync`；尚未接入执行体的任务类型会记录为“跳过”，不会伪造成功。

### 7.2 任务类型枚举表

| 任务类型 | 说明 | 典型计划 |
|----------|------|----------|
| 数据更新-行情 | 收盘后拉取当日 K 线、板块行情入库 | 交易日 16:00 |
| 数据更新-新闻 | 高频拉取四类新闻（去重入库） | 交易日盘中每 10 分钟 |
| 数据更新-研报 | 拉取增量研报元数据 | 每日 08:00 |
| 数据更新-论文 | 抓取增量量化论文元数据 | 每日 06:00 |

### 7.3 任务配置模型表

| 字段 | 说明 | 约束 |
|------|------|------|
| name | 任务名称 | 唯一 |
| task_type | 任务类型 | 枚举（见 7.2） |
| cron | cron 表达式（标准 5 段：分 时 日 月 周） | 合法性校验 |
| params | 任务参数（JSON，如策略 id、数据类别） | 按类型校验 |
| trading_day_only | 仅交易日执行 | 布尔；仅 cron 触发默认生效，手动触发用于人工强制执行 |
| calendar_path / trading_calendar_path | 任务级交易日历文件 | YAML 文件路径；优先级高于全局配置，低于内联 trading_calendar 覆盖 |
| calendar_refresh 参数 | 自动更新交易日历 | `source=akshare_sina` 或离线测试 `source=inline`；`market` 默认 cn_stock；`calendar_path` 必须指向项目目录内；可用 `range_start/range_end` 限定写入区间 |
| calendar_reference_refresh 参数 | 官方参考日历导入 | `official_calendar_path/reference_calendar_path` 指向项目内官方参考 YAML；`holidays` 为工作日非交易日；`trading_days/extra_trading_days` 为周末补班交易日；`announcement_text/announcement_html` 可粘贴公告正文，`announcement_path/announcement_file` 可读取项目目录内公告文件，`announcement_url/announcement_urls` 可拉取指定 http/https 公告网页，`announcement_index_url/announcement_index_urls` 可从指定公告列表页按 `announcement_link_keywords` 发现候选公告链接；`announcement_profiles_path` 指向项目内交易所公告源 YAML，`announcement_profile` 选择其中一个 profile；`announcement_url_timeout_seconds`、`announcement_url_max_bytes` 和 `announcement_discovery_limit` 控制 URL 读取边界；`range_start/range_end` 必填，除非日期列表可推断区间 |
| calendar_announcement_profile_check 参数 | 交易所公告源核验 | `announcement_profiles_path` 指向项目内 profile YAML；`announcement_profile` 可指定单个 profile，不填则检查全部 profile；`announcement_profile_min_links` 控制候选公告链接最低数量；`announcement_profile_check_limit` 控制每个列表页/显式公告 URL 的检查数量；`announcement_url_timeout_seconds` 和 `announcement_url_max_bytes` 控制读取边界；只读返回 `ok/warning/error` 状态，不改写交易日历 |
| system_health_check 参数 | 系统健康告警 | `calendar_path/trading_calendar_path` 指向待检查日历；`official_calendar_path/reference_calendar_path/calendar_reference_path/exchange_calendar_path` 指向官方参考 YAML；`calendar_warn_days` 控制过期前提醒窗口；`calendar_stale_days` 控制更新时间偏久提醒窗口；`calendar_diff_limit` 控制差异样例条数；告警通过 `notify/system_alert` 推送 |
| timeout_seconds / timeout_minutes | 超时时间 | 默认不启用；与 `timeout_mode` 共同决定超时处理方式 |
| timeout_mode / hard_timeout | 超时执行模式 | 默认 `thread`：标记超时并通知；`process` 或 hard_timeout=true：独立子进程执行，超时后终止子进程 |
| retry_times / retry_interval_seconds | 重试次数与间隔 | 默认不重试；按任务参数显式开启，支持指数退避 |
| mutex_group | 互斥组（可选） | 同组同时仅一个执行 |
| executor_key | 自定义执行体 key（可选） | `custom` 任务或未命中内置类型时使用；key 必须在白名单配置中登记 |
| data_maintain 参数 | 数据维护策略 | `news_retain_days`、`remote_cache_retain_days`、`qa_history_retain_days`、`execution_keep_per_job` 默认启用；`backtest_keep_per_strategy`、`qlib_keep_per_type`、`workflow_keep_per_mode` 仅显式配置时裁剪；`vacuum` 默认关闭 |
| enabled | 启用状态 | 布尔 |

### 7.4 执行历史与重试策略表

| 机制 | 说明 |
|------|------|
| 执行历史 | task_runs 表：任务 id、触发时间、开始/结束时间、状态（成功/失败/超时/跳过/重试中）、输出摘要、错误信息；默认保留 90 天 |
| 自动重试 | 任务异常退出且标记可重试时，按 `retry_times`、`retry_interval_seconds` 和 `retry_backoff` 自动重跑；重试占用同一执行链记录 |
| 手动重跑 | 历史记录支持"按当时参数快照重跑" |
| 失败通知 | 重试耗尽仍失败、跳过或超时时经 WebSocket `notify` 主题推送并记录 |

### 7.5 任务互斥与超时控制表

| 机制 | 说明 |
|------|------|
| 同任务互斥 | 同一任务上一次执行未结束时不重复触发，本次标记"跳过"并记录 |
| 互斥组 | 同组任务（如"回测"组）同一时间仅允许一个执行，其余触发标记"跳过"并记录 |
| 超时控制 | 执行超过 timeout_seconds / timeout_minutes 标记"超时"并推送通知；默认线程模式不强杀仍在运行的同步函数，显式进程模式会终止子进程 |
| 全局并发上限 | 同时执行任务数上限（默认 4），超出排队 |

### 7.6 自定义执行体注册

自定义任务通过 `scheduler_executors_path` 或环境变量 `ALL_IN_ONE_SCHEDULER_EXECUTORS_PATH` 指向 YAML 白名单配置，示例见 `egs/config/operations/scheduler_executors.example.yaml`。配置项将 `executor_key` 映射到项目目录内的 Python 文件或模块函数，调度器只加载白名单中的 key；未登记 key 会写入“跳过”，执行体内部异常按现有失败、重试和 notify 规则处理。为避免任意代码路径扩散，文件路径必须位于项目根目录内，生产环境不默认启用样例执行体。

**接口表**：

| 接口 | 方法 | 职责 | 输入 | 输出 |
|------|------|------|------|------|
| /api/scheduler/tasks | GET/POST | 任务列表 / 新建任务 | 过滤条件 / 任务配置 | 列表 / 新任务 |
| /api/scheduler/tasks/{id} | GET/PUT/DELETE | 详情 / 修改 / 删除 | 任务 id | 详情 / 操作结果 |
| /api/scheduler/tasks/{id}/enable | POST | 启用/停用 | 任务 id、目标状态 | 操作结果 |
| /api/scheduler/tasks/{id}/run | POST | 手动触发一次 | 任务 id | 执行记录标识 |
| /api/scheduler/tasks/{id}/runs | GET | 执行历史 | 任务 id、分页 | 执行记录列表 |
| /api/scheduler/runs/{run_id} | GET | 单次执行详情 | 执行记录 id | 详情（含输出与错误） |
| /ws/scheduler | WS | 任务执行状态推送 | 任务 id 订阅 | 状态变更帧 |

## 8. 模型配置模块后端设计

模块总职责：系统设置、LLM 多模型管理（热切换）、MCP 服务配置、Skill 配置。依托核心层配置管理与 settings 表、智能层 LLM 客户端管理器、集成层 MCP/Skill。

### 8.1 系统设置

**职责**：平台级键值设置，持久化于 settings 表（key-value），读取走"数据库 > 配置文件 > 默认值"三级合并（复用 a001 三级配置思路并扩展）。

**设置分组表**：

| 分组 | 设置项示例 |
|------|------------|
| 通用 | 数据目录、时区、交易日历源 |
| 行情 | 行情刷新周期、缓存 TTL、推送帧间隔 |
| 数据源 | 各数据源启用与优先级、失败冷却时长 |
| 安全 | 上传大小上限、策略危险调用黑名单开关 |
| CLI 构建器 | CLI 可执行路径、默认超时、并发上限 |
| 推送 | WebSocket 心跳间隔 |

### 8.2 LLM 多模型管理

**职责**：维护多套 OpenAI 兼容模型配置，按用途指定默认模型，支持热切换（无需重启进程）。

**配置模型表**（llm_configs 表）：

| 字段 | 说明 |
|------|------|
| name | 配置名称（唯一，如 deepseek-fast / glm-deep） |
| base_url | OpenAI 兼容接口地址 |
| api_key_env | 访问密钥环境变量名；密钥保存到 `.env` 或进程环境，界面脱敏展示，不写入日志 |
| call_count / success_count / failure_count | 调用次数、成功次数和失败次数 |
| total_duration_ms / last_duration_ms | 累计耗时与最近一次耗时 |
| last_called_at / last_status / last_error | 最近调用时间、最近状态和最近错误摘要 |
| model_name | 模型名 |
| enabled | 启用状态 |
| remark | 备注 |

**用途默认模型表**（settings 中按用途记录默认配置名）：

| 用途 | 使用场景 | 默认取向 |
|------|----------|----------|
| 快速模型 | 新闻分析 LLM 模式、推荐路径一辅助、摘要类任务 | 低成本、高速 |
| 深度模型 | 推荐路径二精选、模型市场分析报告、策略生成 | 高质量推理 |
| 问答模型 | 知识库 RAG 问答 | 均衡 |
| 嵌入模型（预留） | 检索向量化扩展 | 支持向量的模型 |

**热切换机制表**：

| 环节 | 说明 |
|------|------|
| 配置变更 | API 修改 llm_configs 或用途默认 → 写库 |
| 事件广播 | 发布进程内"模型配置变更"事件 |
| 客户端重建 | LLM 客户端管理器收到事件后懒重建对应客户端实例（下次调用即用新配置），进程不重启 |
| 调用降级 | 调用失败自动切换到同用途其他启用配置（fallback），全部失败按各调用方的降级策略处理（如 RAG 降级为纯检索） |

### 8.3 MCP 服务配置

**职责**：MCP 服务清单、启用状态与连接参数管理，供远程知识库与 Skill 使用。

**配置模型表**（mcp_services 表）：

| 字段 | 说明 |
|------|------|
| name | 服务名称（唯一） |
| transport | 传输类型：stdio（本地子进程）/ http（远程服务） |
| command / url | stdio 命令与参数，或 http 服务地址 |
| env | 环境变量（JSON，凭证脱敏存储） |
| timeout | 连接与调用超时 |
| enabled | 启用状态 |

**连接管理表**：

| 机制 | 说明 |
|------|------|
| 连接池 | 按启用服务维护客户端连接；懒连接（首次使用建立） |
| 健康检查 | 周期探活；失败进入冷却（默认 60 秒内不重试） |
| 状态可见 | 服务连接状态（未连接/已连接/失败）经 API 与 WebSocket 可查 |

当前首版已实现配置级连接测试、单次工具调用和失败冷却：stdio 传输执行 `initialize`、`tools/list` 和按工具名的 `tools/call`，HTTP 传输执行带会话头的 JSON-RPC 探测与单次调用，SSE 传输完成可达性检查；传输失败会进入默认 60 秒、指数退避且最高 900 秒的冷却期，冷却状态和剩余秒数经 API 与前端可见，服务启停或成功探测/调用会清除失败状态。长连接池复用、SSE 工具调用和 provider-specific 远程源适配仍按后续集成阶段推进。MCP 配置样例见 `egs/config/platform/mcp_services.example.yaml`。

### 8.4 Skill 配置

**职责**：技能清单与参数管理；Skill 可绑定 MCP 工具，由智能层 Agent 按需调用。

**配置模型表**（skills 表）：

| 字段 | 说明 |
|------|------|
| name | 技能名称（唯一） |
| description | 技能描述（供 Agent 决策选用） |
| source | 技能来源（本地注册路径 / MCP 工具绑定） |
| params_schema | 参数定义（JSON，含名称/类型/必填） |
| enabled | 启用状态 |

**调用约定表**：

| 环节 | 说明 |
|------|------|
| 参数校验 | 调用时按 params_schema 校验参数 |
| 调用入口 | 智能层 Agent 在编排中按需调用；API 层提供手动执行入口 |
| 结果回传 | 同步返回执行结果；长任务经 WebSocket 推送状态 |

**接口表**（模型配置模块汇总）：

| 接口 | 方法 | 职责 | 输入 | 输出 |
|------|------|------|------|------|
| /api/settings | GET/PUT | 系统设置读取 / 更新 | 分组键 | 设置项 / 操作结果 |
| /api/llm/configs | GET/POST | LLM 配置列表 / 新增 | 配置字段 | 列表（脱敏）/ 新配置 |
| /api/llm/configs/{id} | PUT/DELETE | 修改 / 删除 | 配置字段 | 操作结果 |
| /api/llm/configs/{id}/test | POST | 连通性测试 | 配置 id | 测试结果 |
| /api/llm/defaults | GET/PUT | 用途默认模型查询 / 设置 | 用途、配置名 | 默认映射 |
| /api/mcp/services | GET/POST/PUT/DELETE | MCP 服务配置管理 | 服务字段 | 列表 / 操作结果 |
| /api/mcp/services/{id}/status | GET | 连接状态查询 | 服务 id | 状态 |
| /api/skills | GET/POST/PUT/DELETE | Skill 配置管理 | 技能字段 | 列表 / 操作结果 |
| /api/skills/{id}/run | POST | 手动执行技能 | 参数（按 schema） | 执行结果 |
