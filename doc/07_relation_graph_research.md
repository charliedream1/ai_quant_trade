# AIQuant智投 关系图谱调研

2026-10-25实施修订：不再通过市场新闻或任意候选补足图谱深度，稀疏时保留真实浅层关系。新闻实体和来源标记需要可核对的片段，关联证据贯穿API/导出/页面；收益相关使用对齐交易日期的收益区间。固定圆环与图例锚点导致的空白已修复，实际绘图区约95%；原始调研保留作历史依据，当前方案见[17号设计](17_monitor_graph_resource_design.md)。

调研日期：2026-09-11

## 1. 调研目标

当前系统已有基础关系图谱入口，但节点和边较少，主要展示股票与少量板块/概念关系。后续优化需要回答三个问题：

1. 量化交易中常见的图谱关系有哪些，哪些适合当前个人本地系统。
2. 哪些图谱算法可以提升可解释性和风险联动识别，而不是只做视觉装饰。
3. 在当前 Gradio + Plotly + SQLite 架构下，怎样做最小可落地增强。

## 2. 量化图谱方案

| 方案 | 核心思想 | 适用场景 | 本项目取舍 |
|------|----------|----------|------------|
| 行业/概念/主题显式关系图 | 股票、行业、概念、主题作为节点；行业归属、概念归属作为边 | 解释个股所处板块、热点扩散、推荐结果归因 | 首期优先实现，数据已有板块/概念来源，成本低 |
| 产业链/供应链图 | 上游、中游、下游、供应商、客户、替代品作为关系 | 识别原材料、需求、政策冲击的传导路径 | 首期做结构预留，先用人工维护或公开资料边；后续接公告/年报 |
| 股东/机构关系图 | 股东、基金、公司作为节点；持股、同一机构重仓作为边 | 识别资金同源、抱团、机构风格暴露 | 需要稳定数据源，先预留 relation_type |
| 新闻/事件共现图 | 新闻、事件、关键词、股票作为节点；共现次数或情绪同向作为边 | 发现主题交易、事件冲击、舆情扩散 | 可用已有 news_items 做轻量实现 |
| 收益相关性网络 | 用历史收益率相关矩阵构图，边权为相关系数或距离 | 组合风险、联动风险、同涨同跌簇发现 | 首期用 Top-K 或最小生成树控制边数 |
| 因果/领先滞后图 | 用滞后相关、Granger 检验或事件窗口估计方向 | 发现领先指标、跨品种传导 | 对数据质量和统计检验要求高，后续增强 |
| 多关系动态图 / GNN | 多种关系同时作为图通道，叠加时序特征训练预测模型 | 选股排序、收益预测、风险传播学习 | 当前 MVP 不训练 GNN，只借鉴关系类型和特征设计 |

## 3. 研究脉络

### 3.1 相关性网络与 MST

金融市场相关性网络常用股票收益率相关矩阵构图。Mantegna 的金融层级结构研究用距离变换把相关矩阵变成网络距离，再用最小生成树提取市场的层级结构；后续大量研究用 MST 或过滤网络识别行业簇、市场中心节点和组合分散度。

对本项目的启发：

- 相关性边应该独立于行业/概念边，不混为一种关系。
- 直接展示完整相关矩阵会过密，应该用 Top-K、阈值或 MST 过滤。
- 节点大小可使用度数、加权度或中心性，边宽表示相关强度。
- 相关性可用于“联动风险”而非直接替代买卖信号。

### 3.2 显式金融关系与可解释图谱

股票预测和推荐研究中常把公司间关系分为行业、供应链、股权、新闻共现等多种边。Temporal Relational Ranking for Stock Prediction 这类工作强调用公司关系改进股票排序；近年的金融知识图谱和多关系动态图研究则进一步把财报、公告、新闻、行业链和公司实体融合为动态图。

对本项目的启发：

- 图谱页应允许关系类型筛选，而不是固定一张混杂图。
- 关系边要保留 description 和 source_note，帮助用户判断“为什么有关联”。
- 推荐、个股分析和关系图谱应共享关系定义，避免页面各算一套。
- GNN 训练不是当前优先级，但多关系结构适合先沉淀为数据资产。

### 3.3 事件共现与主题扩散

事件共现图把新闻、关键词、股票、板块连接起来。其优点是成本低、解释强，缺点是容易受热点噪声影响。适合用滚动窗口、情绪过滤和最小词频阈值做降噪。

对本项目的启发：

- 新闻共现边应设置窗口，例如最近 7/30 天。
- 边权可由共现次数、新闻情绪和时间衰减组合。
- 图谱摘要需要提示“事件热度边不代表基本面关系”。

## 4. 当前系统落地方案

### 4.1 首期目标

首期不引入新重依赖，不训练图神经网络，围绕当前 `stock_relations` 表和 Gradio 页面做增强：

1. 增加关系类型筛选：industry、concept、supply_chain、shareholder、news_cooccurrence、correlation、task、analysis。
2. 服务层输出节点度数、节点大小、边权分组、节点分组和图谱摘要，节点分组覆盖关联行业、关联公司、关联板块、关联新闻、关联任务、产业链节点、股东机构和风险/风格因子。
3. Plotly 图增加边 hover 信息、节点类型图例、中心节点突出显示。
4. 节点表补充 degree、node_size、change_pct；边表补充 relation_label、weight、description。
5. 在关系图谱页增加“图谱摘要/解读”区域，说明主导关系、边数、节点数、过滤条件。

### 4.2 后续增强

| 阶段 | 增强项 | 说明 |
|------|--------|------|
| P1 | 新闻共现边 | 从 news_items 的 symbols/keywords 生成滚动共现边 |
| P1 | 相关性边 | 对自选池或候选池计算收益率相关，Top-K 或 MST 过滤 |
| P1 | 任务证据边 | 将明确包含中心标的的推荐、回测、Qlib 和定时任务作为关联任务证据 |

## 5. 数据与算法约束

- 免费公开数据源稳定性有限，图谱页必须展示数据来源和更新时间。
- 相关性网络需要明确样本窗口，避免用太短窗口形成伪相关。
- 新闻共现和主题边只能提示信息关联，不能作为基本面因果关系。
- 股东/供应商客户关系只有在数据源可靠时才启用，不能用缺失数据伪造关系。
- 图谱查询必须限制节点数和边数，避免 Gradio 页面过慢。

## 6. 推荐实现顺序

1. 先增强 `RelationGraphService.graph` 的过滤、节点统计和摘要输出。
2. 再增强 `src/frontend/services.py` 的 Plotly 网络图布局和表格字段。
3. 最后更新 `src/frontend/app.py` 的关系图谱控件，增加关系类型多选和摘要区。
4. 完成测试后再考虑新闻共现边和相关性边的后台构建。
