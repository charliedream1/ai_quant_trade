# 全局提醒与AI助手形象设计

2026-10-29，Codex。状态：用户已确认完整方案，提醒服务/全局界面/原创机器人已实现并通过定向回归及浏览器操作；本文不含实现代码。范围为全局提醒、AI悬浮入口形象和文档工具选择，沿用Gradio及现有模块化页面。

## 一、现状与目标

现有首页展示账户风险观察线，因子监控保留因子告警，系统页展示交易日历等健康提示；普通操作失败由Gradio局部弹窗处理。当前没有跨模块提醒中心，关闭弹窗后缺乏统一回看入口。AI入口是右下角54像素文字按钮，支持拖动和悬浮面板。

核查位置包括frontend/shell.py:shell_html与SHELL_JS、features/assistant.py:render_floating_assistant、theme.py:initializeFloatingChat、common/callbacks.py:_callback_run、service/home_views.py:risk_alerts、service/monitoring.py和system路由。正式帮助已由mkdocs.yml构建本地静态站点，发布样例位于egs/config/operations/mkdocs.publish.example.yaml；尚无Read the Docs托管配置。

## 二、提醒显示位置

推荐固定在主页面右上角、顶部导航下方，使用小型通知卡片；顶部新增铃铛与未读数，点击打开右侧提醒抽屉。AI助手保持右下角，系统告警不要求用户先打开AI聊天，也不把告警作为模型回复。

| 类型 | 展示与关闭 | 可回看及处理 |
| --- | --- | --- |
| 成功/普通信息 | 短暂卡片，建议6秒后收起，可手动关闭；悬停/键盘操作时暂停计时 | 保存可追溯结果，查看任务或报告 |
| 重要提醒 | 黄色/橙色图标与边框，手动关闭，不自动消失 | 提醒中心保留未读/未处理状态及来源 |
| 严重风险/关键服务故障 | 红色卡片及持续的顶部风险摘要条，可收起卡片 | 直到来源恢复或按业务规则处理，摘要和中心仍可查 |
| 本次操作必须决定的事项 | 对应操作流程中的确认或阻断提示 | 使用既有业务校验；不单凭通知按钮确认交易或绕过风控 |

卡片包括程度图标、短标题、原因摘要、发生时间、查看详情和右上角关闭叉。默认宽约340像素，最多同时三条，其余合并到中心；数值、时长和上限放在YAML。窄窗口使用可见区域宽度，不挡输入区、发送按钮、主要操作和抽屉关闭入口。红黄蓝绿之外还保留文字和图标，键盘可访问，普通消息不抢输入焦点。

关闭卡片表示收起当前展示，不能等同解除风险或删除记录。已读、收起、来源已解决分开；关闭后刷新或切页不重复弹同一事件。提醒源发生实质变化或新的运行失败时可产生新事件；首次打开时不把全部历史挤成弹窗。首页仅为观察的阈值继续标识为观察提醒，不提升成自动交易风控。

## 三、数据、性能与接入范围

增加独立提醒服务和受控API，记录来源类型/ID、事件指纹、程度、标题、简述、发生时间、关联对象和可信导航目标。列表、未读数、增量获取、已读及收起共用同一记录；数据库使用幂等键去重，不因重复刷新积累相同事件。提醒写入失败只记日志，不改变原任务的执行结论或账本。

首批接入现有因子告警、系统/交易日历健康提示和长任务完成/失败。长任务优先覆盖回测、定时任务与AI报告，保持各自真实状态和来源。监控类只消费已有持久化结果或健康缓存，不因显示提醒额外拉行情、训练或调用模型；不凭推测制造告警，不将所有普通校验错误都写成全局重要事件。

全局通知层放在持久外壳，模块iframe只通过同源、受校验消息触发刷新；避免每页各建一套弹窗和轮询。首批默认一个15秒增量拉取通道，后台标签暂停，恢复时补取；用户操作产生的已知事件可立即通知外壳。实际风控阻断仍在后台即时执行，不依赖前端轮询。若后续要求外部事件秒级推送，再单独评估SSE连接，不宣称首批所有后台提醒都能瞬时到达。

连接失败时有限退避，数据量与保留期有界；已有记录可以查看，不用循环错误弹窗。对象跳转只接受平台定义的module/view和类型化ID，不执行消息HTML、任意链接或脚本；内容转义，错误摘要不包含密钥和原始认证凭据。

目前平台没有完整的多用户身份体系，阅读/收起状态首批按当前浏览器客户端范围保存；这不是权限身份。以后如部署多用户，需绑定实际用户隔离，不把匿名客户端标识当认证。通知中心为可回看的业务提醒，不冒充外部合规审计系统。

## 四、AI助手卡通形象

推荐原创蓝白Q版小机器人：圆润头盔、深蓝屏幕脸、青蓝眼睛和小天线，配轻微柔和阴影，与现有蓝白商务风格协调。使用本地SVG矢量素材，缩小后仍清楚，亮暗模式均可辨识；不引入外部图片CDN或动图依赖，也不复制第三方商标角色。

原54像素点击区域、拖动、位置限制、打开/关闭对话框继续保留。悬停显示“AI助手”，支持键盘和可访问名称；不以卡通图替代可操作按钮。默认静态，悬停可轻微抬起，尊重减少动画偏好。只有后台实际运行时才显示工作状态，不为活泼效果伪造忙碌或消息提示。

设置中保留“机器人 / 简洁图标”切换，并预留项目内自定义图片路径；自定义素材限制格式、大小和来源，不将任意SVG脚本作为受信任资源。系统提醒的未读数由顶部铃铛承担，助手头像不混用交易风险颜色来代表模型判断。

## 五、MkDocs与Read the Docs

| 名称 | 定位 | 对本项目的意义 |
| --- | --- | --- |
| MkDocs | 从Markdown和配置生成静态文档 | 现有使用/原理分类、截图、搜索与本地帮助继续复用 |
| Read the Docs服务 | 自动构建、版本化与托管文档的平台 | 可托管MkDocs产物；需要仓库连接、构建配置和发布目标 |
| readthedocs主题 | MkDocs自带的一个页面主题 | 只是展示风格，不等于已使用托管服务；原生主题仅支持两级导航 |
| Sphinx | 另一类文档生成器，常与Read the Docs配合 | 更适合需要深入API交叉引用的项目；目前没有迁移必要 |

推荐继续使用MkDocs维护现有Markdown和本地帮助；外部发布时可选择Read the Docs，也可使用现有静态站点部署方案。两者可组合，不需要先把文档改写为另一种工具格式。若用户偏好Read the Docs式侧栏，主题选择单独预览；当前已有分组导航及自定义资源，不能只改主题名就宣称兼容。

本轮只明确工具分工并更新使用说明；不连接外部账户、不上传仓库或发布站点。以后接Read the Docs时只安装文档构建依赖，不安装整个量化/模型环境；公开产物继续排除audit、research、任务草案、数据库和密钥。项目位于Git仓库子目录，托管配置位置需结合项目边界核实，未经授权不向仓库根目录写新配置。
