### 当前实现与设计差异

- 已接入组件目录、七套方案、草稿及冻结版本、日期批次目标引擎、独立 Portfolio/Risk、单/三角色终审、Gradio 工坊、资源池、REST、CLI、离线 HTML 和持久前向模拟。操作见 `docs/usage/strategy_composition.md`，证据见 `docs/audit/composition_2026-10-22/`。
- 初期行情归档采用带内容摘要的 JSON 面板，与现有 Parquet 层并存；尚未新增全市场批量数据源。新模型按成熟训练样本与环境摘要保存原生权重，不加载未知 pickle；训练和预测逻辑分开，暂未提供独立分布式训练调度。
- 子策略风险预算使用子账户实际单位净值逆波动率；证券级 ERC 单独估计协方差并求解，不将两者混称。市场状态组件以母池等权价格为代理，不能冒充外部宽基指数。
- 撮合为日线研究批次，使用前一日可见信息与下一日开盘，内部归属调拨不扣市场费用，未成交余量按当日批次失效。真实交易所挂单、券商撤单、完整交易日历及特殊证券规则不在本轮自动开放。
- 缺少历史行业分类时阻断行业回测；普通组合标注行业覆盖缺口。240 根未复权日线不包含公司行动或历史完整成员，只验证小样本因果链路。回放决定的原生成时点保守限定在决策日 UTC 日终之前，并校验有效期和完整输入摘要。
- C 的 CVaR、动态 Stacking、额外深度网络与长期压力测试尚未启用。实时实盘风险控制不由本地模拟监控替代。

## 1. 目标与范围

建立可组合的策略工坊，支持规则和形态初筛、机器学习或小型神经网络评分、Agent 研究终审、Portfolio 组合配置、Risk 风险约束，以及同一链路下的回测和模拟盘验证。

一个投资方案由有类型的组件和参数组成，可以串行筛选、并行评分、投票、合并候选，也可以配置多个子策略的资金预算与共享风控。保存方案后，可在市场研究的资源池入口执行筛选，在仿真入口进行组合回测。不要求使用者把所有逻辑改写成一个大策略文件。

本设计将 market place 对应为“策略市场/策略工坊”的组件目录及方案入口；“市场研究 → 资源池”是选定股票池后执行筛选的入口。两处使用同一份方案和执行器，AI 的 MCP/Skill 管理继续承担工具与研究方法管理。

首期覆盖日线、多头与现金、明确证券范围及研究/模拟执行。杠杆、卖空、衍生品、分钟级执行及真实券商自动交易不随本设计自动开放。已有单策略回测及研究 Agent 保留。

## 3. 组件类型与标准链路

推荐主链路为：股票池及数据时点 → 可交易资格 → 规则/形态筛选 → 模型评分 → 并行融合 → Agent 研究终审 → Portfolio 目标权重 → Risk 约束 → 目标订单与模拟执行。

| 类型 | 负责什么 | 输出 | 组合规则 |
| --- | --- | --- | --- |
| Universe | 固定股票池、ETF 池、资源池及历史成员快照 | 当期基础股票池 | 必须说明时点及成员来源 |
| Filter | 可交易性、规则、形态、行业/主题约束 | 候选及通过/拒绝/未知原因 | 可串行，也可按交集、并集或 K/N 合并 |
| Scorer / Alpha | 规则强度、树模型、小网络预测 | 逐标的原值、分数语义和证据 | 可以并行；不同量纲不能直接相加 |
| Ensemble | 排名融合、投票、共识与冲突处理 | 融合分数、覆盖率和分歧 | 与资金分配区分，不能把均值分数当资金权重 |
| Decision Agent | 研究终审、选择/拒绝/退出建议及理由 | 结构化研究决定和有效期限 | 可减少候选，不能加入上游范围外的新买入标的或放宽风控 |
| Portfolio | 标的权重和多策略资金预算 | 含现金的目标组合及计算诊断 | 每条配置路径有一个明确的分配器，多方案通过上层预算组合 |
| Risk | 准入、仓位、组合、账户及运行风险 | 限额、裁剪、减仓、拒单或冻结决定 | 多条策略取约束交集；硬性限制不参与投票 |
| Execution | 净额、再平衡、费用、可卖数量及成交 | 订单、成交、未成交和实际组合 | 接受最终目标篮子，不让并行分支分别向同一账户下单 |

规则先筛选、模型再评分只是一个默认模板。框架同时支持规则组之间并行、模型组之间并行、两个完整子策略并行，以及在融合后增加第二道筛选。首期使用有类型的无环图，禁止循环依赖及任意表达式执行。

## 4. 第一批组件目录

下面是实施清单。标记“复用”指已有逻辑或后端可复用，仍需适配新契约并测试；“新增”并未在本轮实现；“扩展”不计入第一批完成数量。

### 4.1 股票池与规则/形态

| 组件 | 定义与用途 | 计划 |
| --- | --- | --- |
| 固定/资源/ETF 池 | 版本化候选母池；历史模式使用当期成员，不用今天成分冒充历史 | 复用并扩展快照 |
| 可交易与流动性过滤 | 上市长度、有效行情、停牌、状态标记、成交额等；缺失字段明确未知 | 新增 |
| 市场状态过滤 | 用当时已知的指数趋势和波动阈值区分趋势、震荡及高波，不用全期拟合后回填状态 | 新增 |
| 均线趋势 | 长短均线及斜率，用作趋势过滤或强度评分 | 复用双均线 |
| MACD 动量 | 可计算的 DIF/DEA 及动量条件 | 复用 |
| RSI 均值回归 | 超买超卖、回归触发及退出条件 | 复用 |
| 布林带突破 | 突破与带宽条件，区分趋势突破和回归假设 | 复用 |
| 放量动量突破 | 过去价格强度与量比联合确认 | 复用 |
| 唐奇安通道突破 | 当前收盘突破此前窗口高点，窗口不包含当前观察值 | 新增 |
| 波动收缩后突破 | ATR/振幅收缩和量价突破的明确数值定义；标为收缩形态近似 | 新增 |
| 趋势回踩恢复 | 既有上升趋势中回踩均线后恢复，参数化确认与失效条件 | 新增 |
| 双底颈线突破 | 窗口低点、间隔、容差与颈线突破；枢轴必须等右侧确认后才能生效 | 新增 |
| 横截面低波动 | 历史波动率排序；不声称兼有财务质量或低尾部风险 | 新增 |
| 行业相对强弱 | 行业层选取与行业内候选，依赖可得分类及日期 | 复用行业轮动并适配 |
| ETF 动量/趋势 | ETF 池中的相对动量和趋势门槛，保留池与资产类型 | 复用两套 ETF 逻辑 |

首批新增六类规则/形态逻辑，加一套通用资格过滤；均提供筛选结果、数值定义及失败原因。缠论和复杂图形识别作为可选适配，未通过完整历史与确认延迟验证时不计为可回测组件。

财务质量、价值、公告事件、资金和筹码等组件留作数据驱动扩展。缺少历史公布时间或数据源时显示 unavailable，不用当天财务、当日行业成分或新闻反推过去。人工主观形态名称不能替代可测试定义。

行业历史分类缺失时，依赖该字段的组件只能作为有当前证据的筛选或前向模拟能力，历史回测标为 unavailable，不计为该模式验收通过。

### 4.2 模型评分

| 模型 | 第一批定位 | 衔接方式 |
| --- | --- | --- |
| LightGBM | 默认截面评分器 | 复用模型后端，训练/预测与委托解耦 |
| XGBoost | 第二个树模型与对照分支 | 与 LightGBM 使用相同可比较特征、标签及评估切分 |
| 小型 MLP 集成 | 小网络分支，提供不同模型结构的对照 | 复用现有 CPU 后端与种子集成，标准化仅拟合训练段 |
| 小型 GRU / TCN | 多时点序列扩展 | 后续在更长历史、样本数和耗时验收通过后增加 |

先复用已实际训练过的三套后端，不为增加名称而同时新增大量模型。规则特征可以输入模型，模型也可以只处理初筛后的当期候选。

训练母池和当期预测候选必须分开。默认在当时可用的训练股票池及成熟标签上训练，只对通过初筛的当前标的预测。所有母池标的的历史连续维护，不能因当天被过滤就停止积累其历史。若研究条件模型，只能使用历史各时点实际通过规则的训练样本，并单独记录选择偏差与样本量。

### 4.3 并行融合

| 方法 | 行为 | 默认及边界 |
| --- | --- | --- |
| 交集/并集/K-N | 按通过票数合并规则候选 | 先做统一资格过滤；并集不得恢复硬性禁止标的 |
| 等权排名 | 对同一参考池的有效分数转成百分位后平均 | 首个并行评分基线 |
| 固定权重排名 | 按事先设定权重融合，显示每支贡献 | 不使用最终测试收益决定权重 |
| 多数/加权投票 | 按事先定义的赞成、反对、弃权与法定票数决策 | 持有、不满足、未知和预测失败不能混成同一票 |
| 共识与分歧惩罚 | 使用模型排名一致性或离散程度降低冲突候选优先级 | 与收益预测分别记录，不包装成校准概率 |
| 历史有效性权重 | 仅基于已到期的样本外 IC/误差/净收益调整权重 | 扩展；保留窗口、滞后和过拟合控制 |
| Stacking | 用样本外基础预测训练二层小模型 | 扩展；不使用基础模型训练内预测拟合融合器 |

回归预测、RSI、量比和模型自报 confidence 不直接相加。每支标明分数方向、目标、单位、预测周期及参考池；同分使用固定证券排序确保可复现。不同预测周期默认分配到不同子组合，不做任意换算后融合。

现有模型默认预测去均值后的相对收益，因此正分不等于绝对收益为正，百分位靠前也不等于值得买入。排名融合保留原值语义，绝对入场门槛由有依据的市场状态、规则或另行验证的绝对目标决定。

均线、MACD、突破等相关信号按信号家族限制总权重，避免靠增加同类指标重复投票。某标的在某支没有观察时标为弃权；缺失分支是否允许降级、是否重新分配权重及最低覆盖率事先写入方案。全部失败不能生成满分候选。

### 4.4 Portfolio 组合分配

| 组件 | 解决的问题 | 实施层次 |
| --- | --- | --- |
| Top-K 等权 | 选中资产等权，作为可解释基线 | A |
| 非负评分权重 | 在有效信号与已批准候选内按标准化强度配置，保留现金门槛 | A |
| 逆波动率 | 给高波资产较低权重 | A |
| 固定子策略预算 | 趋势、回归、ETF 等独立子组合各有资金预算 | A |
| 等风险贡献 ERC | 根据完整协方差估计求风险贡献接近目标预算 | B |
| 层次风险平价 HRP | 根据资产相关性聚类后配置 | B |
| 收缩协方差最小方差 | 多头、上限和现金约束下控制组合方差 | B |
| 子策略风险预算 | 基于各子策略已形成的净值/收益序列分配风险 | B |
| 最小 CVaR | 基于足量历史情景控制尾部期望损失 | C/扩展 |
| Black-Litterman | 在可靠先验与校准观点、不确定度下融合配置 | 后续扩展 |

逆波动率不等于 ERC；资产分散也不等于子策略分散。Portfolio 类型可替换，但同一路径不会顺序执行多个分配器互相覆盖。要比较等权、HRP、最小方差，就形成三个共享选股输入的试验方案；要同时使用，就按明确预算构造三个子组合，再在主组合汇总。

含现金的目标权重总和为一，资产持仓权重可以小于一。优化器必须提供样本数、资产顺序、协方差估计、条件诊断、收敛状态和约束检查；不收敛或样本不足不能静默输出上一次权重或任意等权。允许的降级路径须预先选择并在结果显示，例如“HRP 不可用，本次按已批准的等权备选运行”。

### 4.5 Risk 风险策略

| 组件 | 触发与动作 | 实施层次 |
| --- | --- | --- |
| 证券资格与缺失数据闸门 | 硬性不合格/关键字段未知禁止新建风险，保留减仓处理 | A |
| 总仓位、单票与持仓数上限 | 在账户、待成交与目标篮子口径统一限仓 | A |
| 行业/主题/资产类别上限 | 按真实分类限制集中度，缺失分类按已声明策略处理 | B |
| 流动性与成交参与率上限 | 基于截至决策时已知成交量/金额限制订单，不能读取未来全天量 | A 基础 / B 扩展 |
| 固定/ATR 止损 | 形成退出意图，按可交易时间执行 | A |
| 移动止损/时间退出 | 持仓最高已知价或持有期触发，保存独立状态 | A |
| 组合波动率缩放 | 根据组合估计风险降低总敞口，首期不放大到杠杆 | B |
| 最大回撤阶梯降仓 | 账户高水位回撤触发分级降低敞口，并有恢复/冷却条件 | A |
| 单日损失冻结 | 按当日基准净值及浮动/已实现损益冻结新增风险 | A |
| 相关性与聚类集中限制 | 限制高相关资产簇敞口；与行业上限并存 | B |
| 调仓带与换手预算 | 小偏差不交易、正常换手受限，紧急风险退出优先 | A |
| 跳空、延迟、陈旧行情、运行故障 | 风险提示、拒绝新增风险、延迟执行或人工关注 | A 基础 / B 扩展 |
| 尾部情景/VaR-CVaR 限额 | 历史/压力情景估计风险并约束新增目标 | C/扩展 |

以上给出 13 类风控能力。止盈可作为可选退出组件；硬性安全退出优先于普通止盈及换手约束。各项均需参数方案、状态、触发证据和回测契约，不仅是配置页上的一个开关。

## 5. 七套开箱方案

每个方案都提供保守研究基线和一个对照配置，参数明确命名，不称为最优。方案描述、参数、提示词及示例数据分别进入 YAML、环境配置或测试 fixture，不硬编码到源码。

| 方案 | 选股与融合 | Portfolio | Risk |
| --- | --- | --- | --- |
| 规则趋势基础 | 趋势 + 唐奇安 + 放量，交集或 K/N | Top-K 等权 | 基础限额 + ATR 止损 + 回撤降仓 |
| 形态模型级联 | 收缩/回踩/双底规则组 → LightGBM 与 MLP 排名 → Agent 终审 | 非负评分或逆波动率 | 单票/行业 + 流动性 + 波动缩放 |
| 三模型共识 | LightGBM、XGBoost、MLP 并行，固定权重及分歧检查 | 等权或最小方差 | 单日损失 + 回撤 + 换手预算 |
| 震荡均值回归 | 已知时点的震荡状态 → RSI/布林条件 → 小模型对照 | 等权，低总敞口 | 时间退出 + 固定止损 + 行业限额 |
| 行业轮动增强 | 行业强弱 → 行业内规则 → 模型排名 → Agent 风险理由 | 行业预算内逆波动率 | 行业集中 + 相关簇 + 换手 |
| ETF 多资产配置 | 已登记 ETF 池 → 趋势与相对动量 | 等权、ERC、HRP 对照 | 资产类别上限 + 波动目标 + 回撤 |
| 多策略总组合 | 趋势、均值回归、ETF 子方案并行，各自生成目标 | 固定子预算，后续可切子策略风险预算 | 子策略额度 + 证券净额后的账户统一风控 |

这些方案可作为筛选任务运行，也可在冻结版本后进入回测/模拟。Agent 是可配置阶段；Agent 为必选时失败不得自动绕过。历史研究与真实当期终审采用第 9 节的独立验证口径。

## 6. 级联与并行的精确定义

### 6.1 级联

每级只接收上级合法输出，并保存输入数量、通过、拒绝、未知、预算和耗时。规则阶段优先使用廉价、可缓存的历史特征；训练一次后批量预测，不对每只股票重复训练。最后只把有限候选及持仓例外发送给 Agent。

上级硬性禁止不得被后级恢复。候选为空属于正常筛选结果，不能自动降低阈值凑出推荐。候选被筛掉只表示失去本级入选资格，并不自动构成现有持仓卖出指令；是否退出由已冻结的组合再平衡约定或显式退出意图决定。

### 6.2 并行

分支基于同一不可变数据时点、参考股票池与账户快照计算，不直接修改账户或共享模型状态。并行是逻辑上分支独立；实际执行并发数、训练线程及数据源速率受预算控制，不承诺开启更多线程就更快。

合并键至少包含证券、决策时点、预测周期和分数语义；定义交集、并集、固定权重、最低有效分支数及冲突处理。模型超时、缺依赖、无有效样本分别留痕，不能作为买入零分或默认支持票。

### 6.3 子策略资金组合

先为每个子策略分配资金预算，再得到各自证券目标；同一证券的目标在主账户加总、净额并统一校验风险。每个子策略保留虚拟持仓和损益归属，实际成交只发生一次，费用和部分成交按预先定义的分配规则归属，不能把独立回测收益简单平均称为组合净值。

总资金预算不超过可用资本；子预算内保留现金时不能自动分给其他子策略。动态预算只能读取此前形成的子策略样本外收益，不能用完整测试段估计相关性后再回测该段。

## 7. 目标权重与风控执行顺序

先生成拟议目标，再应用所有硬性边界、冷却状态和组合风险缩放；最终对四舍五入后的订单及预计可实现组合复查限额。默认风控只裁剪、归零或缩小拟议风险，削减部分留现金，不在末尾重新归一化以抵消降仓。

风险配置按权限分为账户不可弱化上限、策略预算、方案设置和本次研究覆盖；合并时取更严格边界。普通参数的“后者覆盖前者”规则不能用于放宽账户硬性上限。Agent 的评分或理由也不能覆盖风险规则。

正常换手预算不能阻止紧急减仓；流动性、可卖数量和市场交易限制仍约束减仓。卖不掉、涨跌停、停牌、T+1、跳空等情况下标记“风险超限待执行”，展示实际与目标之差，不伪造已完成平仓。此时继续管理原有风险并禁止相应新增风险，不能通过停止监控让既有持仓失管。

每个交易日都检查全部持仓和未成交订单，即使候选为空、模型在预热、Agent 失败或尚未到调仓日。日损失包括浮动损益；回撤高水位、冷却和解除条件需要持久化。重启不能重置止损、当日损失或账户回撤状态。

## 8. 统一数据与接口契约

| 对象 | 必需信息 | 关键约束 |
| --- | --- | --- |
| 组件说明 | 类型、标识、版本、输入输出类型、参数 schema、依赖、适用市场/频率、历史能力、耗时等级 | 明确 ready、unavailable、experimental；只允许登记的实现 |
| 运行上下文 | 运行/方案版本、决策时点、最早可执行时点、市场、数据快照、账户快照、预算、随机种子 | 所有读取受截止时点约束 |
| 候选记录 | 证券、资格状态、规则原值、原因码、观察时点、来源 | 通过、拒绝与未知严格区分 |
| 评分记录 | 原始值、归一化值、目标语义/周期、参考池、有效期限、模型版本、证据 | 拒绝 NaN/Inf、重复主键、过期和不兼容周期 |
| Agent 决定 | 选择/观察/拒绝/退出、理由、引用、反证、缺口、有效期限、后端和模型元信息 | 输出域限定，不能创造新证券或修改配置 |
| 组合目标 | 证券目标权重、现金、子策略预算、现有冻结头寸、计算诊断 | 区分没有目标、维持、目标为零和无法交易 |
| 风险决定 | 规则版本、输入目标、限额、触发原值、调整后目标、动作及恢复条件 | 记录硬约束冲突与实际执行缺口 |
| 运行事件 | 时点、组件、状态、输入输出数量、实际错误/工具内容、耗时、证据引用 | 页面展示真实事件，完整记录可下载 |

所有组件参数按实例命名空间保存，允许同一算法以不同窗口出现两次而不共享状态。过滤集合与评分集合采用不同类型；排序、优化器、风险链的顺序固定并进入摘要。对未知字段、重复标识、循环、不可达阶段和不匹配的输入类型，在运行前明确拒绝。

新增类型使用轻量领域对象及适配器，不把目标权重塞入旧信号的 metadata 后假定旧引擎会识别。旧单策略继续使用已有 StrategyPort。组合方案通过一个登记的组合策略入口进入现有策略生命周期和 backtest_tasks 外键关系，再由声明支持截面与目标权重的引擎执行。

校验分为静态图/参数检查、离线契约预检和实际小样本执行。不能在旧的单事件 dry-run 中启动训练或 Agent；预检成功也不代替真实拟合、预测及成交验证。

## 9. Agent 的终审职责与历史边界

默认先支持单终审 Agent，再支持研究分析、独立反证、汇总三角色方案。调用后端可选现有模型 API 或已接通的 Codex CLI；工具使用普通文本 ReAct，模型 JSON 使用 json-repair，再作字段、引用、有效期限与取值校验。固定提示词和工具白名单存 YAML，不给该阶段委托工具。

终审必须回答选择/拒绝理由、规则与模型是否冲突、证据缺口、风险以及何时失效。默认可否决或收紧候选，不用自报 confidence 替代模型校准概率或优化器风险参数。需要评分修正时，范围和权重须提前配置并单独评估。

Agent 的合法选择/拒绝结果会实际进入下游候选及组合构建，不只是为既有推荐追加一段解释；Portfolio 决定可实现的资金分配，Risk 对最终目标保持强制约束。真实委托的授权与通道能力继续独立管理。

每次终审的授权范围、候选数、请求数、正文/工具上限、超时和费用预算固定。超时或格式修复耗尽时明确失败；必选 Agent 阶段失败则不新增风险，仍运行持仓风控。允许的降级仅在方案创建时明确选择，不能静默退成规则或模拟回复。

历史模式分开处理：

| 模式 | 输入与使用 | 可证明什么 |
| --- | --- | --- |
| 纯量化基线 | 不调用 Agent，按历史时点计算规则与模型 | 量化链路及样本外结果 |
| 已存决定回放 | 使用当时真实保存且未过期的决定、数据摘要、模型/提示词与完成时点 | 该决定在当时执行约定下的历史重放 |
| 今天生成历史解释 | 限定历史数据进行研究；仍可能包含模型训练知识中的未来信息 | 仅为历史解释/探索，不能视为无前视的样本外交易结果 |
| 当期研究/前向模拟 | 使用当前合法数据，记录实际完成时点，再按之后的可执行时点推进 | 可积累前向证据；不能提前假定历史长期收益 |

历史行情不能配今天新闻或最新财务做 Agent 决定。即使禁用联网，通用 LLM 的先验知识仍可能污染历史推演，单靠缓存或提示词无法消除。Agent 完成日晚于计划执行时点时，决定失效或顺延，不能回填成昨天已成交。

## 10. 训练、回测与执行正确性

1. **共同时间轴**：以真实日期聚合全体标的，先形成一致快照，再运行截面组件。改变股票池顺序不应改变结果。缺失当天行情不得用其他日期数据占位成交。
2. **决策与成交分离**：默认在交易日收盘后计算，下一可交易日开盘执行。开盘估值、实际现金与订单占用用于成交前校验，当天收盘只能在之后进入研究；禁止把收盘结果回填当天开盘。
3. **训练与到期标签**：按日期切分整个截面；有重叠标签时按预测终点剔除跨界样本。训练内变换、调参、融合权重和组合估计不得读取验证或最终测试。TimeSeriesSplit 的 gap 不能替代金融标签的全部净化规则。
4. **形态确认**：双底、局部高低点、ZigZag 等若依赖右侧确认，结果时点从确认完成算起。修改未来数据不能改写此前已形成的信号。
5. **可用历史和预热**：显式计算特征、训练、验证、标签成熟及组合协方差所需长度。当前行情路径最多 240 根，初期只证明小样本流程；缺失长期样本时阻断相关研究或标明能力不可用，不伪造多年检验。
6. **证券与市场约定**：交易日历、买卖单位、可卖数量、结算、停牌及涨跌停规则按证券类型配置和版本化；不把全部 A 股和 ETF 当成统一 100 股/T+1。缺少实际撮合数据时明确为日线研究近似。
7. **持仓账本与再平衡**：支持加仓、部分减仓、持有、现金预留和卖出后买入；净额处理、费用及整手后再次检查权重。记录持仓批次和可卖数量，不能用一笔平均持仓掩盖 T+1。
8. **止损路径**：首期按已知日线触发、之后可交易时点执行；不保证止损价成交。扩展日内止损须处理跳空及同根 K 线止盈/止损都触发的先后不明，不能选择对收益最有利的路径。
9. **状态和重复执行**：方案冻结版本，按账户/决策时点/阶段幂等；已发订单、剩余风险和子策略归属保存。重试不重复下单，参数修改不影响旧运行。
10. **对照与归因**：对照规则独立、模型独立、融合、无 Agent 和有 Agent 决定回放；用同一份数据、费用及可交易假设比较。分别展示各阶段价值和成本，不把组件更多当作有效性证明。

特征与风险估计必须采用一致、已注明的复权口径。现金/持仓精确记账还需未复权执行价格与分红、拆并股等公司行动；不混用调整后价格和未处理的实际数量。数据尚不具备时明确标为不含相关公司行动的研究近似，不能宣称现金流精确复现。

新回测引擎按可声明的 batch/target-weight 能力注册，继续返回现有指标、净值和成交格式，并增加组合及阶段诊断。旧 simple 和 Qlib 不支持所需能力时明确 blocked，不自动换成 simple 或虚构曲线。新链路通过回归后才讨论逐步统一共享账本；不在首期大改全部旧策略。

## 11. 参数、版本与存储

保留现有模型默认、源码声明、保存默认、命名 YAML 方案、本次覆盖的继承流程，扩展到组件实例。资金预算、股票池、训练及风险约束分别归组，账户硬限制独立校验。预览不导入模型、不请求行情、不训练或调用 Agent。

方案采用草稿、校验通过、已发布版本、停用状态；发布后不可原地改写，编辑生成新版本。冻结快照包括组件顺序与参数、母池与成员时点、数据/特征/模型摘要、训练切分、提示词/Skill、后端、种子、成本和执行策略。缓存键包含这些摘要及输入截止时点，禁止跨版本/时点误复用。

| 存储 | 拟保存内容 |
| --- | --- |
| SQLite 方案及版本表 | 名称、状态、版本、定义摘要及与登记策略的关系 |
| SQLite 运行/阶段索引 | 运行状态、父子关系、时点、数量、耗时、错误和产物路径 |
| 项目内运行目录 | 冻结定义、输入清单、阶段候选及淘汰、分支评分、Agent 决定、目标/实际权重、风险与订单事件 |
| Parquet 行情/特征归档 | 可共享但受截止时点约束的历史面板，避免每次重复调用全量个股详情 |
| 已有回测/模拟记录 | 关联组合运行及参数快照，保持旧任务接口兼容 |

第一批新增索引表通过可重复迁移建立；不得删除旧表、策略或历史报告。模型重训练任务与预测任务分离，原子发布模型产物，仅使用项目内白名单文件，不加载未知来源 pickle。所有文件路径校验项目边界，秘密仅通过 `.env` 和既有密钥配置读取。

| `src/frontend/features/composition.py` 与对应 service/handler | 轻量工坊、方案编辑和运行诊断，首次进入后构建 |
| `egs/strategy_components/`、`egs/examples/strategy_pipelines/` | 组件参数与七套预置方案；Agent 提示词另存 YAML |
| `tests/strategy/composition/`、`tests/portfolio/`、`tests/risk/` | 契约、参考计算、时间不泄漏、组合记账与约束测试 |

下面是已经接入的接口族，完整请求及响应口径见已同步的 05 号 API、08 号标准端口与 10 号参数设计：

| 接口族 | 拟定操作 |
| --- | --- |
| `/strategy-components` | 查询类型、参数、依赖/数据能力及状态 |
| `/strategy-pipelines` | 草稿、复制为新版本、校验、无执行副作用的参数预览、发布/停用 |
| `/strategy-pipeline-runs` | 指定冻结版本、股票池、时点和执行模式创建运行 |

运行模式区分只筛选、生成目标、历史量化回测、已存 Agent 决定回放和前向模拟。写入自选或交给模拟账户必须是显式操作；研究结果或生成 HTML 不等于执行订单。

## 13. 页面及报告

“策略构建”下增加“策略工坊”二级入口，右侧顶部仅用组件、方案与运行结果组织内容，不叠加多层页签。组件卡片显示用途、输入输出、能力状态、适合市场及数据需求；Risk 与 Portfolio 独立分类，不混进普通选股脚本列表。

首期采用步骤表、分组、上移下移和依赖选择编辑方案，提供只读流程图和参数解释；复杂拖拽画布后置。左侧选择模板，右侧显示方案、完整参数、校验和启动入口。“市场研究 → 资源池”提供方案选择及执行筛选，复用执行器。

运行结果包括筛选漏斗、每支贡献与弃权、分歧、Agent 理由/引用、证券及子策略权重、现金、风险贡献与约束事件、净值/回撤/换手和实际耗时。风险贡献只在估计有效时展示，缺失时说明原因，不画伪雷达。

支持追溯每只证券在哪里通过、淘汰或持有，以及相同证券在各子策略的意图及最终净额。图表/术语提供悬浮说明，默认蓝白商务主题并沿用暗色配置。截图待真实页面实施后采集，设计阶段不制造操作图。

任务异步、带阶段实际事件、可中断和查询；重复点击不创建同一活跃任务。取消必须传递给可终止的模型/CLI 调用，无法立即停止的部分标为取消中，不能只停止页面刷新。风险监控与持仓管理独立于筛选任务存活。

## 14. 数据与性能约束

全市场扫描需要可用的批量行情及历史归档；当前逐标的 `stock_detail()` 会附带其他数据，不适合作为全市场每级筛选的重复数据请求。先实现有边界的资源池和本地历史面板，使用同一数据网关供多组件共享；全文新闻及财务只为末级少量候选按需读取。

目录、方案选择和参数预览不触发模型导入、训练、行情或 Agent。特征按数据/配置摘要缓存；模型按训练截止时点缓存；Agent 只对最终有限候选调用。设置市场数据速率、并发、内存、线程、请求与 token 上限，实际过程显示队列等待和组件耗时。

验收在同机、同池、同缓存条件下对照原单策略与新链路，分开记录冷启动、暖预测、训练、Agent、数据网络和页面时延。纯规则及额外风控的暖执行开销拟以相对基线不超过 20% 为初始预算，先测基线再固定；重训练和新增 Agent 单独按自身预算验收，不把外部等待隐藏进所谓实时返回。

## 15. 分批实施与验收门槛

| 阶段 | 必交付 | 完成标准 |
| --- | --- | --- |
| A：最小完整闭环 | 类型/目录/参数冻结、日期批次引擎、目标账本、六类新增规则、三模型评分适配、基础融合、四种基础 Portfolio、A 级 Risk、单 Agent 终审 | 一个规则→模型→Agent→组合→风险的当期小池方案真实跑通；纯量化历史基线及旧策略兼容通过 |
| B：丰富组合能力 | ERC/HRP/最小方差/子策略风险预算、行业/相关集中风控、三角色终审、完整七套预置、工坊/资源池/API/CLI/报告及前向模拟 | 各方案实际导入/校验/执行；对照评分组合与资金组合；原因、目标、成交、风险与成本可核对 |
| C：扩展研究 | 足量历史与历史成员、CVaR、动态融合/Stacking、GRU/TCN 的择需实现及压力测试 | 先满足数据与依赖条件，再独立验收；未具备时不计为完成、不进入默认推荐 |

A 阶段提供基础 API/CLI 以便完整验证，B 阶段补齐页面与主要操作。默认优先 A→B，C 是独立扩展，不让高级优化器或数据不足阻断基础级联功能。

### 必须实际通过的测试

- 单元：DAG 类型/循环、参数边界、时点与标签到期、形态确认、不同量纲/预测期、弃权和法定票数、固定种子与稳定排序、风险参数更严格合并。
- Portfolio：等权/逆波动/已知参考协方差的手算对照；现金守恒、权重和、非负、预算、约束不可行、零波动、单标的、缺数据、矩阵退化、求解失败及明确降级。
- 账户/Risk：显式数量也不能绕过限仓；加仓/部分退出/T+1批次、费用与整手、挂单占用、子策略重叠净额、紧急退出优先、卖不掉不假平仓、重启状态和重复请求。
- 防泄漏：改变未来行情/标签/新闻不改变历史结果；改变证券遍历顺序不改变组合；排名、协方差及训练内变换不读取未来；Agent 过期、晚返回、非法标的、伪引用和超时不生成新风险。
- 集成：传统规则、三模型、级联、并行融合、行业、ETF 与总组合逐项跑；核对各级数量、真实拟合/预测次数、订单与组合净值、最大回撤与成本，并与无风险覆盖和单策略基线比较。
- 真实证据：明确行情来源、日期、训练及样本外长度；分别验证真实模型、真实 Agent 和模拟替身。CVaR 及长期结论不以当前 240 根数据充数。
- 页面/CLI：真实点击模板选择、配置预览、运行、失败、取消、历史恢复、HTML/数据下载及跨主题截图；CLI 同版本同快照重放一致；首屏不训练、不运行 Agent。
- 检查与回归：按改动范围运行 mypy、Ruff lint/format、pytest 单元和集成、pip-audit、Bandit、Semgrep；工具/依赖缺失如实报告。Windows/Linux 均验证路径、进程与文件编码，停止服务并按用户规则确认清理临时文件。

## 16. 开源设计依据

以下资料用于验证分层和组件组合的可行性，不作为机构收益或本项目实现状态的证明；核查日期 2026-10-22。

- [LEAN 多 Alpha](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/alpha/key-concepts)：多信号保留来源，并由组合层解释融合；不把框架的逻辑多模型自动称为线程并行。
- [LEAN 组合构建](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/portfolio-construction/key-concepts) 与 [风险组件](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/risk-management/key-concepts)：组合目标进入风险层，多条风险组件可以顺序修正目标。本项目另加全链路硬限制与执行后审计。
- [Qlib Portfolio Strategy](https://qlib.readthedocs.io/en/latest/component/strategy.html)：预测分数与持仓构建分离，有目标权重接口与 TopkDropout。复用这种职责分离，不要求把本项目全部组合执行迁入 Qlib。
- [PyPortfolioOpt HRP](https://pyportfolioopt.readthedocs.io/en/latest/OtherOptimizers.html) 与 [CVaR](https://pyportfolioopt.readthedocs.io/en/latest/GeneralEfficientFrontier.html)：作为高级分配器和风险度量的参考；不因算法名称就声称优于简单基线。
- [scikit-learn TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)：支持时间顺序与样本 gap；本项目另外按标签覆盖区间检查泄漏。

第一批不预先安装 LEAN、PyPortfolioOpt、Riskfolio 或新深度学习框架。可先用既有数值与模型依赖实现基础闭环；高级算法是否复用外部库，须在实施时核验许可证、适配成本、安全性及真实可用版本，再在项目环境记录依赖。
