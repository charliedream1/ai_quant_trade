## 范围与入口

统一阅读面板由AI项目文件、会话附件和知识库文档打开，支持文件上传预览。HTML、Markdown、PDF、图片及普通文本直接阅读；DOC/DOCX、XLS/XLSX和PPT/PPTX按需转换PDF。Office和生成报告始终只读，Markdown原件允许编辑；受保护的任务文档和运行目录禁止改写。

预览以文件ID访问，不暴露任意绝对路径。面板提供适宽、全屏、下载和关闭。PDF.js等前端资源本地固定版本，点击文件后才加载；原会话、导航和模块延迟构建继续保留。未保存的Markdown在关闭或切换时提示处理，不默默丢弃。

## 原件与知识文本

上传保存原始字节、文件名、类型、哈希和来源；知识库原件与已有提取文本关联，RAG继续检索提取文本。旧记录无原件时仅展示现存正文，明确提取文本身份，不能伪造原版DOCX/PDF。新原件字段以兼容迁移添加，不重写历史正文。

AI附件使用准备阶段同一字节快照生成阅读记录；仅向用户显示受控预览链接。上传预览不自动调用模型，不自动创建知识库记录。项目文件读取范围与Markdown可编辑范围由YAML声明，排除环境密钥、Git、虚拟环境、缓存和docs/task开头文件。

## 保存与一致性

编辑只接受Markdown类型，Office、PDF、HTML、代码与图片拒绝保存。客户端提交打开时版本哈希，服务端保存前再次核对；变化时拒绝覆盖并让用户重新载入。保留修改前版本，采用原子替换，记录新版本和时间。

知识库Markdown保存后同步原件、正文摘要和检索分块；项目文件保存只影响选中的Markdown。不能把Office提取出的Markdown伪装成可编辑的Office原件。大小、编码和更新冲突具有明确错误状态。

## 转换与缓存

本次使用独立LibreOffice工作进程，Windows采用项目内便携版本，Linux配置已部署的程序路径；Gotenberg留作后续研究，不作为已实现后端。转换由后台有界工作队列处理，首次打开显示真实状态，重复请求按原件哈希及转换配置复用产物，不在启动或普通切页转换。

转换输入、独立用户配置和输出位于项目内较短的转换工作区，缓存与日志保存在服务数据目录；明确超时，结束本轮进程树，不影响用户已有Office进程。宏文件不在支持白名单，配置禁用宏执行。进程隔离不等同于网络或操作系统沙箱。失败保留原文件下载和原因，不生成假PDF或成功状态。
