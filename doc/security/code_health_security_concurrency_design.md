# 代码结构、安全与并发治理方案

2026-10-31复核，Codex。用户“请优化”已授权实施，A→F重点整改已完成并通过650项全量回归。后续端到端复核另修自然问句检索、章节选择回调和阅读关闭按钮遮挡；未升级或修改环境包、轮换密钥、重写Git历史或对外发布。本设计不含代码。审计基线72d742e5；初审和实施证据见docs/audit/code_health_2026-10-30及code_health_fix_2026-10-30；最新复核见docs/audit/code_health_e2e_2026-10-31。

## 一、总体判断

当前适合继续在既有模块上渐进治理，保留Gradio、图形策略工坊、原生Skill、OpenAI兼容文本生成、传统ReAct、json_repair、统一回测账本和研究纪律。目录已按业务分区，但安全边界、任务生命周期和部分模块依赖尚未形成统一约束；单功能测试通过不能替代这些边界的验证。

先修访问与执行边界，再修实际错误和并发一致性，最后拆大文件与收紧质量门禁。大范围改名、重写前端、统一改异步或直接更换数据库都不作为首轮动作。

## 三、实施阶段

### A：统一访问控制与隐私边界

优先覆盖api/app、settings、llm_models、mcp_servers、strategies、live、ws_hub及Gradio挂载。默认本地访问与显式远程部署区分；建立可复用认证与权限策略，限制CORS和Host，写操作校验来源，读取敏感资料同样校验身份。健康探针的公开范围单独约定，不把整个平台都当公开接口。

MCP凭据、连接字符串及内部异常不直接返回客户端；保存凭据引用与公开配置的区分，敏感字段采用递归脱敏。环境文件导入不能允许普通调用者任意修改程序入口或进程级敏感变量。进程仅获得对应提供者确有需要的环境变量，避免把全部平台密钥继承给任意插件。

确认Git已跟踪.llm_env的非空配置来源和有效性；停止后续跟踪与消除密钥扫描盲区属于必要修复。实际密钥撤销、轮换和历史重写在核实影响后单独安排，不在本轮审计擅自执行。审计数据库、完整提示词、附件、原始回复须建立脱敏、保存期限与发布策略。

验收：未授权的管理/执行请求不能成功；可信网页正常操作，非可信Origin和WebSocket来源被拒；列表、错误、日志、报告不返回合成凭据；Git门禁检测受跟踪环境文件；确认既有CLI、文件阅读、Skill、通知及会话功能仍正常。

### B：隔离策略执行与外部程序

StrategyStore.get与创建返回的展示过程不隐式执行策略；静态接口校验和实际运行分开。AST黑名单只负责提示，不再视为沙箱。已信任样例、用户上传和模型生成代码区分来源；实际执行移到受控工作进程，限制可写目录、可见凭据、外网、CPU/内存及运行时限。普通子进程本身不等于安全沙箱，Windows和Linux分别验证约束。

MCP与原生CLI的程序路径、参数、模型配置和网络目标执行显式策略；保留用户需要的本地MCP/模型服务，不能简单封禁所有私网。保护云元数据地址、重定向和DNS解析后的目标，阻止未授权程序启动；避免将参数数组错误地改成shell拼接。

验收：展示策略不产生运行副作用；导入时的模块顶层动作、动态内置调用及子进程继承凭据不能越过边界；常见规则、模型、ETF、行业轮动、组合与Agent方案完成小样本回测，账本结果可比对。

### C：修复已复现错误与异步阻塞

图谱四层二跳相关性复用现有按日期对齐的return_correlation，保留证据和样本门槛，禁止为消除类型错误直接把字典转无日期列表。层级失败需要记录缺失和原因，不静默丢弃结果。

API错误处理集中脱敏并正确序列化校验异常；先稳定业务信封、错误码和request_id，再分阶段引入HTTP状态码语义，兼容既有CLI/SSE。WebSocket验证消息对象、字段和配额，统一finally清理；慢客户端设置发送时限和独立背压。

Gradio首次构建、附件内容校验、知识解析、CSV/Excel解析、索引和同步数据库操作离开事件循环；使用有界线程执行I/O，CPU密集任务使用独立工作进程。所有上传入口在完整读入和解析前控制体积；环境导入使用唯一临时文件、完整预校验和并发保护。

验收：四/五层图谱日期错位与不足样本正确处理；畸形JSON和自定义模型校验得到稳定错误；上传/冷页构建并发时健康与普通请求的事件循环延迟受控；超限数据提前拒绝；并发环境导入无串包和丢更新。

### D：任务所有权、取消、背压与落盘一致性

统一任务状态语义、所有者、租约、心跳、取消请求与可见事件。修复仅凭本进程ACTIVE就把其他进程任务判为失败的逻辑；调度与风险监控避免多Web进程各自重复运行。首期继续使用现有SQLite，使用条件更新和短事务建立状态转换，不先迁移数据库。

明确软超时与可终止执行：线程超时不代表函数停止，运行中的写任务不得提前释放互斥并重试。复用已有进程超时能力，为账户/发布等副作用提供幂等和检查点；取消后的远端计费状态如实保留。

后台队列、上传、模型调用、连接、缓存、会话锁和事件日志均设置容量及保留策略。SSE事件等待改用异步队列或独立受限通道，避免挤占Web共用线程池；统一截止时间向实际HTTP/CLI执行透传。图谱并发分支只返回局部结果，由主线程在共同截止时间内合并，过期分支不再修改返回对象。

验收：双进程查看不会误改状态；并发触发仅执行一次；超时、取消、重启、磁盘失败均保留准确终态；满队列明确拒绝，慢SSE/WebSocket不拖住普通API；不存在任务结束后继续修改账本的情况。

### E：按职责拆分模块与接口

优先拆theme.py内嵌CSS/JS、eastmoney.py的图谱与数据族、render_ai等巨型页面函数；保留DOM标识、路由、配置键、持久化格式和回调行为。静态语言表体积大不等于复杂逻辑，不为行数机械拆分。

服务Facade逐步改为按领域组合，减少106个前端模块通过全量Mixin导入的耦合；API与UI共享逻辑下沉到中立应用服务，不互相导入。Provider请求/响应、任务、行情、指标和异常使用明确类型，避免依赖Any和私有LLM方法。数据库建表和升级逻辑拆为有版本的迁移；参数、默认提示词、样例数据按规范进入YAML/测试资料。

验收：架构依赖规则可自动检测，已有公共导入路径保留兼容；同一冻结输入的信号、Portfolio/Risk、账本、研究门槛一致；页面初始体积、冷/暖访问延迟和交互截图不退步。

### F：统一质量与依赖门禁

修复全量Ruff和mypy存量债，区分实际类型错误、Mixin协议与可选Qlib/Langfuse环境。补足适用的类型声明和环境检查，不以全局ignore屏蔽问题。按基线推进新代码零新增债，再分批清存量；CI覆盖完整源码、异步/并发/安全语义测试，而非只校验配置文字或少数选定文件。

主环境Pillow12.3.0与Gradio小于13的依赖约束冲突，应先验证兼容候选组合和完整图片调用链，再创建候选环境回归，禁止直接绕过依赖约束。独立Pillow13工作进程保留，但不能等同主环境告警已消除。图形前端deepmerge公告作为构建链问题跟踪上游；无安全版本时不强制升级到未知版本。

验收：每个支持环境运行依赖一致性检查与漏洞审计；Ruff格式/类型/SAST有完整记录和逐项误报说明；新增安全复现转换为修复后的预期语义测试；Windows与Linux分别验证启动、上传、策略执行、终止和报告。保留既有财务指标与研究纪律的回归基线。

## 四、顺序与变更控制

建议A→B→C→D→E→F分批实施，每批单独review、单元/集成、小样本端到端和日志归档。F中的增量门禁从A开始启用，依赖候选验证可与C的输入链治理并行；不进行大规模模型调参。真正密钥操作、Git历史重写与生产配置迁移在形成可审阅结果后单独确认。

每批先固定原有接口与财务结果基线；若需修改spec、README、依赖与截图，同批同步。测试服务结束即停止，临时文件删除遵循既有人工确认要求；本轮实施不扩展为生产账户迁移或历史密钥操作。
